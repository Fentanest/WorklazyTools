# 에이전트 호출·복구 런북

역할·모델 배정·검증 정책은 공통·역할 문서를 따른다. Claude 총괄·감사와 Astra 검수를 유지한다. 이 파일은 호출과 복구 절차만 설명한다.
Opus는 첫 위임 전에, Fable은 필요한 경우 읽는다. 같은 환경에서 확인한 경로·버전은 재사용한다.
아래는 기존 저장소에 기록된 호출 방식이다. 실제 설치 경로·지원 옵션은 호스트에서 확인하고, 부재하면 임의로 추정하지 않는다.

## 작업 공간과 입력

저장소 경로는 현재 작업 공간의 git rev-parse --show-toplevel로 확인한다.
지시서는 docs/jobs/todo 또는 허용된 외부 작업 공간에 두고 경로·버전·요청 모드·구현 허가·기준 소스·역할·모델·실행 도구·허용 쓰기 범위를 전달한다. 병렬 작업은 각각의 브랜치/worktree·소유 범위·검사 자원·통합 담당을 함께 명시한다.
구현과 검수 작업 공간을 구분한다. 검수용 복사본에는 대상 미커밋 변경까지 정확하게 포함한다.
검토 중인 계획서와 소스를 덮어쓰지 않는다. 원본에 대한 기술적 권한 제한과 임시 쓰기 공간을 별도로 확인한다.

## 병렬 실행 준비·통합

공통 정책은 PROJECT_RULES.md의 「독립 작업의 병렬 구현」을 따른다. 구현이 허가된 작업에서만 아래 구현 절차를 수행한다. `!계획만!`은 같은 반박 라운드와 정본화까지 수행하되 구현용 worktree·구현 잡·통합·배포를 시작하지 않는다. 문서·스킬 설치 확인을 위해 실제 구현 잡을 발행하지 않는다.

1. `git worktree list --porcelain`과 각 대상 경로의 `git status --short`, 브랜치·HEAD를 확인한다. 작업표의 기준 커밋·공유 계약·소유 범위가 맞는지 대조한다.
2. 같은 기준 커밋에서 새 작업 브랜치와 worktree를 각각 만들거나, 같은 보장을 주는 독립 checkout을 사용한다. 아래는 확인한 값으로 실행하는 명령 형식이다. 기존 브랜치·디렉터리가 있으면 덮어쓰지 않고 상태부터 확인한다.

       git -C "$ROOT" worktree add -b "$SOL_BRANCH" "$SOL_WORKTREE" "$BASE"
       git -C "$ROOT" worktree add -b "$MUSE_BRANCH" "$MUSE_WORKTREE" "$BASE"

   ROOT·BASE는 확인한 저장소·커밋, 각 BRANCH·WORKTREE는 충돌 없는 고유 이름·절대경로다. main을 직접 두 실행자에게 주거나 force 옵션으로 같은 브랜치를 중복 체크아웃하지 않는다. 관련 미커밋 변경이 있으면 먼저 범위를 식별하고 필요한 승인된 사본만 포함한다.
3. Git 제외 지시서와 로컬 스킬·설정은 자동 복제되지 않으므로 필요한 사본·버전을 각 worktree에 전달한다. 의존성·벤더 준비도 각 작업 공간의 수정 부수 효과를 확인한다. 승인된 설치 없이 환경을 새로 구성하지 않는다.
4. 작업마다 전용 임시 디렉터리·산출물·브라우저 세션/프로필·서버 포트를 배정한다. 공유 /tmp 경로나 변경 가능한 캐시를 사용하는 검사기는 실제 지원 옵션으로 분리한다. 옵션이 없으면 해당 검사만 순차 실행한다. 메모리·CPU를 과도하게 쓰는 검사는 수를 제한한다.
5. 두 구현 호출에 각자의 worktree와 지시서를 전달한다. 잡 ID 또는 세션·프로세스와 소유자를 작업표에 기록한다. 공통 로그·CHANGELOG·review-notes·backlog는 통합 담당에게 취합한다.
6. 각 구현자는 고정된 커밋·변경 목록·검사 결과·미완료 사항을 제출한다. 통합 담당은 별도 브랜치/작업 공간에서 지정 순서대로 merge 또는 cherry-pick 중 한 방법을 적용한다. 통합 전후 대상 HEAD와 diff를 기록한다.
7. 통합 후 실제 변경·연결 경로·충돌 해결의 영향으로 필요한 검사만 추가한다. 공통 최종 검사의 유효한 결과를 한 번 취합하고 Astra 검수와 Claude의 감사·최종 판정을 거친다. 개별 브랜치 통과를 통합 통과로 간주하지 않는다.
8. 인계는 기존 실행과 하위 프로세스의 종료 및 변경·증거 보존 후 수행한다. 통합·산출물 보존을 확인하기 전 worktree를 강제 제거하지 않는다.

## Codex 위임 — Claude의 설치된 연결 사용

기존 연결은 Agent의 codex:codex-rescue다. 도구가 실제로 노출된 환경에서만 사용한다.
기존 호출 형식:

    Agent(
      subagent_type="codex:codex-rescue",
      prompt="--background --fresh --model gpt-5.6-sol 지시서 <실제 절대경로>의 구현 작업. 저장소 <실제 경로>. 기준 소스 <식별값>. 파일 수정이 필요한 구현 작업이다."
    )

예시는 구현 단계다. 계획 검토·결과 검수는 AGENTS.md의 해당 모델을 명시한다.
모델을 생략하지 않는다. 전달자가 원문에 없는 커밋 금지·배포 허용 등을 추가하지 않게 한다.
순수 코드·문서 판독과 빌드·브라우저 재현을 구분해 권한을 지정한다. 재현에 임시 쓰기가 필요해도 제품 수정·커밋 권한을 함께 주지 않는다.
이 Codex 연결의 새 작업은 fresh로 시작한다. 이 옵션을 Muse의 연속·연관 작업에 적용하지 않는다. 실패한 Codex 작업을 재개할 때는 보존된 diff와 완료된 범위를 지시서에 넣는다.
연결을 거치지 않는 nohup 실행·중복 구현 잡을 임의로 추가하지 않는다.

기존 결과 조회 스크립트 위치 기록:

    ~/.claude/plugins/cache/openai-codex/codex/1.0.6/scripts/codex-companion.mjs

버전 경로가 바뀌면 설치된 플러그인에서 실제 파일을 확인한다. 기록된 옛 경로가 현재도 있다고 가정하지 않는다.
실제 경로를 COMPANION, 반환된 잡 ID를 JOB에 넣어 다음과 같이 조회한다.

    node "$COMPANION" status "$JOB"
    node "$COMPANION" result "$JOB"
    node "$COMPANION" cancel "$JOB"

Codex 사용 불가가 명시된 문서·스킬 설치에서는 이 절의 호출·조회·모델 탐색을 실행하지 않는다.

## Muse 위임·세션 이어쓰기 — 확인된 OpenCode 연결

모델은 Muse Spark 1.3이다. 기존에 작동하는 실행 도구·공급자·구독 연결을 유지한다. 정확한 모델 ID를 지어 넣거나 Sol용 Codex 호출의 모델 문자열만 바꾸지 않는다.
OpenCode 호스트에서는 `opencode models`의 실제 ID를 확인해 MODEL에 기록한다. 확인된 같은 연결은 매 호출 다시 탐색하지 않는다. 아래는 OpenCode의 공식 CLI 옵션에 맞춘 형식이며 다른 실행 도구에 그대로 적용하지 않는다.

### 명령 전에 고정할 값

- MUSE_WORKTREE: 이번 작업의 확인된 절대경로. 세션이 기록한 작업 공간과 실제 명령 작업 공간을 대조한다.
- MODEL: 작동 확인된 Muse의 공급자/모델 ID. 기본 모델에 맡기지 않는다.
- TASK_FILE: 최신 지시서의 절대경로와 버전. 최신 PROJECT_RULES.md·AGENTS.md도 확인시킨다.
- SP: 호출별 고유한 외부 기록 디렉터리. 후속 호출 로그로 이전 로그를 덮어쓰지 않는다.
- SESSION_ID: 기존 작업의 실제 세션 ID. 새 작업일 때만 아직 없을 수 있다.
- MODE와 IMPLEMENTATION_PERMISSION: 최신 요청 모드와 구현 허가 상태. 계획만 상태를 세션 기록에서 유실시키지 않는다.

프롬프트에는 작업 ID·지시서 버전·기준 소스·현재 역할·요청 모드·구현 허가·종료 조건을 포함한다. 위 값이 담긴 실제 지시를 PROMPT에 구성한 후 아래 경우 중 하나만 선택한다. 같은 호출에 `-c`와 `-s`를 함께 넣지 않는다.

### 연속·연관 작업은 기존 세션 우선

바로 전 세션이 해당 작업의 마지막 세션임을 확인했고 다른 작업으로 바뀔 여지가 없으면 `-c`를 사용한다. 시각·전역 최신 순서만 믿지 말고 작업 ID·제목·저장소·worktree·내용을 대조한다.

    opencode run --dir "$MUSE_WORKTREE" --model "$MODEL" -c \
      "$PROMPT" > "$SP/muse-out.log" 2> "$SP/muse-err.log"

기존 작업의 특정 세션을 잇거나 여러 작업이 섞여 있으면 기록된 ID를 우선 사용한다. ID가 없으면 아래와 같이 목록을 조회해 해당 작업을 찾는다. 목록 범위가 현재 폴더만이라고 가정하지 않으며, 후보가 모호하면 해당 도구의 세션 열람 기능과 기존 로그에서 내용·경로를 확인한다. 오래된 작업이 안 보인다는 이유만으로 없다고 결론 내리지 않는다.

    (cd "$MUSE_WORKTREE" && opencode session list --format json)

확인한 ID로 이어간다. 기록된 ID가 있으면 일괄적인 `-c`보다 이 방식이 우선이다.

    opencode run --dir "$MUSE_WORKTREE" --model "$MODEL" -s "$SESSION_ID" \
      "$PROMPT" > "$SP/muse-out.log" 2> "$SP/muse-err.log"

### 필요한 경우에만 --fork

기존 대화 맥락을 보존한 채 다른 접근·실험·독립 후속을 분리하려면 부모 세션을 지정해 분기한다. 같은 작업의 정상 후속마다 무조건 분기하지 않는다. 구현자 모델을 바꾸거나 기존 결함·계획만 제한을 지우기 위한 분기도 하지 않는다.

    opencode run --dir "$MUSE_WORKTREE" --model "$MODEL" -s "$SESSION_ID" --fork \
      "$PROMPT" > "$SP/muse-out.log" 2> "$SP/muse-err.log"

마지막 세션이 확실한 경우에는 다음도 허용한다. 병렬 환경에서는 위의 ID 지정 방식을 우선한다.

    opencode run --dir "$MUSE_WORKTREE" --model "$MODEL" -c --fork \
      "$PROMPT" > "$SP/muse-out.log" 2> "$SP/muse-err.log"

분기 결과의 실제 자식 ID를 출력·작업 레코드에서 확인해 부모 ID·목적·작업 ID·worktree와 함께 남긴다. 추정한 ID를 쓰지 않는다. 다음 후속은 자식 ID를 `-s`에 전달하며 부모로 잘못 돌아가지 않는다.
`--fork`는 대화 분기다. Git 브랜치·worktree를 만들거나 파일 상태를 복사·복원하지 않는다. 실제 동시 구현은 공통 병렬 규칙에 따라 별도 브랜치/worktree·소유 범위·자원을 준비한다. 세션의 과거 절대경로와 실제 작업 공간이 다르면 최신 경로를 확인시키고 옛 경로에 쓰지 않게 한다. 도구가 그 작업 공간으로 안전하게 연결하지 못하면 원본 공간에서 대신 구현하지 말고 인계 요약을 통한 새 세션 등 안전한 방식을 사용한다.

### 새 세션이 맞는 경우

완전히 무관한 작업, 적합한 세션 부재, 손상·도구 제약으로 안전한 재개가 불가능한 경우에만 새 세션을 선택하고 이유를 기록한다. 다음은 구현 허가까지 확인된 새 작업의 형식이다. 세션이 적합하게 남아 있는데 편의상 매번 처음부터 시작하지 않는다.

    opencode run --dir "$MUSE_WORKTREE" --model "$MODEL" \
      "$PROMPT" > "$SP/muse-out.log" 2> "$SP/muse-err.log"

### 재개·분기의 안전 확인

같은 세션 ID에 두 호출을 동시에 실행하지 않는다. 동일 작업 인계·재개 전 이전 실행과 하위 작업의 종료 또는 안전한 중지 상태, 실제 소스·diff·미완료 작업을 확인한다. 기존 로그·미해결 쟁점·검증 결과를 버리지 않는다.
재개 첫 지시에서 최신 요청 모드·구현 허가·정본/규칙 버전을 다시 확인시킨다. 과거의 「계획 후 구현」 지시가 현재 `!계획만!`을 덮어쓰지 않게 한다. 계획만 세션을 재개하거나 분기해도 정본화 후 구현 대기를 유지하며, 별도의 명시적 구현 지시가 기록돼야만 해제한다.
지시서가 worktree 밖에 있어 접근할 수 없으면 허용된 공간에 사본을 두고 버전을 확인한다. 권한 검사를 끄거나 공급자·과금 경로를 바꾸어 우회하지 않는다. 세션 조회가 실패하면 실행 불가와 실제 실패 이유를 기록하고, 다른 세션을 추정해 잇지 않는다.
Codex companion으로 Muse 상태를 조회하지 않는다. 기록할 것은 실제 도구·모델·세션 ID·부모/자식 관계·작업 ID·worktree·지시서 버전·요청 모드·실행 식별자·로그 위치다. 필요한 항목만 기존 작업표에 갱신하고 새 관리 시스템을 만들지 않는다.
이 문서의 반영을 확인하려고 모델 호출·세션 분기·실제 병렬 구현을 시험하지 않는다. 설치 호스트에서 옵션이 지원되지 않으면 임의로 설치·업그레이드하지 말고 제약과 대안을 보고한다.

CLI 옵션 확인 출처: https://opencode.ai/docs/cli/ (2026-09-14 확인). 사용자 호스트의 실행 성공을 뜻하지 않는다.

## Gemini 위임 — agy

기존 호스트 연결은 agy다. 구 gemini CLI로 임의 전환하지 않는다.
ROOT는 확인한 저장소, TASK_FILE은 지시서, SP는 허용된 임시 공간, MODEL은 GEMINI.md의 정확한 지정값이다.
기존 기본 형식:

    agy --add-dir "$ROOT" --model "$MODEL" \
        --effort high --print-timeout 15m \
        --log-file "$SP/gemini.log" \
        -p "$(cat "$TASK_FILE")" \
        > "$SP/gemini-out.md" 2> "$SP/gemini-err.log"

시간 옵션은 해당 호스트에서 확인한 duration 형식을 사용한다. 숫자만 넣거나 모든 작업을 긴 시간으로 고정하지 않는다.
출력 스키마 강제가 필요하면 설치 버전이 지원하는 옵션을 확인한다.
쓰기·네트워크·브라우저 권한은 작업에 맞게 제한한다. --dangerously-skip-permissions를 기본 호출에 붙이지 않는다.
권한 때문에 빈 출력이 나면 stderr·로그로 진단하고 허용된 환경에서 해결한다. 권한 해제를 자동 복구 절차로 삼지 않는다.

## 감시·실패·재개

실제 실행 식별자를 기록하고 환경이 지원하는 완료 알림을 우선 사용한다. 알림이 없으면 최소한의 상태 조회만 한다.
상태 문자열뿐 아니라 로그 갱신·해당 프로세스·산출물을 확인한다. pgrep에 잡 ID가 잡혔다고 자기 감시 프로세스를 작업자로 오인하지 않는다.
완료 알림만으로 성공을 판정하지 않는다. 상태 running인데 프로세스가 없거나 결과 레코드가 사라지면 실패로 조사한다.

여기의 재시도 제한은 권한 오류·프로세스 실패 등 **도구 실행 실패**에 관한 것이다. 반박 내용의 검토 횟수와 혼동하지 않는다. 수정 가능한 실행 실패 원인을 확인한 경우 한 번 재시도하고 같은 원인의 호출을 쌓지 않는다. 내용의 추가 반박은 공통 규칙에 따라 1+1회 이후에도 가능하다.
죽은 잡을 재발행하기 전에 살아 있는 중복 작업이 없는지 확인한다. 취소는 정확한 잡 ID에만 수행한다.
재시작 전 기존 변경과 산출물을 보존하고, 이미 완성된 부분을 확인한 뒤 이어가게 한다. 사용자 변경을 reset·clean으로 지우지 않는다.

## 완료 확인

지시서의 요청 모드와 종료 조건부터 확인한다. `!계획만!`의 완료는 필요한 반박을 거친 정본화와 구현 대기 보고이며, 제품 코드·미래 테스트·커밋이 없다고 미완료로 판정하거나 구현을 재발행하지 않는다.
구현 허가된 작업은 지시서 이행, 결과 파일·로그 존재, 검사한 소스와 제출 소스 일치, 대상 수·캡처 수, 요청된 커밋·배포 여부를 확인하고 Astra 검수 결과를 Claude의 감사·판정에 전달한다.
불일치는 필요한 부분만 보완한다. 완료 확인을 이유로 전체 회귀를 다시 시작하지 않는다.
호스트 경로를 새로 확인했다면 필요한 사실만 기록한다. 상세 사고 서사를 CLAUDE.md로 다시 가져오지 않는다.
