- 런타임: 라벨 텍스트 전체(제목·설명, 치환 후)를 **서브셋 cmap 커버리지로 사전 검사** → 전부 커버되면 서브셋 파일 fetch, 하나라도 밖이면 **전체 OTF 폴백**(현행 경로 그대로). 판정은 문자 집합 목록(빌드 산출 JSON)으로 하며 폰트를 열지 않고 가능.
- **R4 와의 구분**: R4 는 pdf-lib/fontkit 의 **런타임 subsetter** 가 한글을 깨뜨린 것. A 는 **빌드 타임에 별도 도구로 만든 완전한 OTF** 를 `subset:false` 로 전체 임베드하므로 임베드 경로는 현행과 동일. 단 **서브셋 도구의 산출이 fontkit·Poppler·PDF.js 에서 유효한지**를 R4 와 같은 방식(Poppler 렌더·PDF.js 텍스트 추출)으로 재증명해야 한다.
- 도구: 호스트에 fonttools 없음 → 후보 ① `/tmp` Python venv 의 `fonttools`(pip, 빌드 재현성은 `requirements` 고정 + 산출 해시 고정으로 확보 — **저장소 npm/pip 의존 추가 없음**, 생성은 오프라인 1회·산출물만 벤더링) ② npm `harfbuzzjs`/`subset-font`(새 devDependency — 「새 라이브러리」 C-C 검토 필요) ③ 순수 Node 로 CFF 서브셋 구현(비추천). 1차 반박에서 ①·② 의 산출 크기·유효성·재현성을 비교.

### B. 압축 자산 사전 생성 + 브라우저 해제
- `.otf.br` 를 벤더링하고 `DecompressionStream("brotli")` — 브라우저 지원 없음(gzip/deflate 만). gzip 은 서버가 이미 하므로 이득 0. **기각 예정**(반박에서 반례 없으면 확정 기각).

- 이미 PDF 클릭 시 fetch. 생성 시작과 병렬로 prefetch 해 체감만 줄이는 안 — 전송량 불변이라 사용자 결정(감량)에 못 미침. 보조 수단으로만.
