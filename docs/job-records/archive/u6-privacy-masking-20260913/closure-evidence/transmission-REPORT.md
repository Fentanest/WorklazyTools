## Findings

U6's actual network call is the fixed manifest acquisition in `runtime.prepare`, before input is mounted. The subsequent memory factory's method named `fetch` clones an already-owned in-memory asset; missing assets fail without an HTTP fallback. PDF.js receives byte data, the prepared worker, `BinaryDataFactory`, and `useWorkerFetch:false`. Fixed imported module URLs and the Blob wrapper are prepared before input. The manifest's 189 physical assets, worker readiness and exact input boundary have separate production evidence in the accepted P3 report.

The U6 page creates result/ZIP URLs from owned, verified local Blob results and uses native download anchors. Result names affect the download attribute, not an outgoing URL. The common shell has fixed logos and explicit navigation/support links. Analytics and AdSense components remain in the repository for other routes, but U6 does not mount them; hard navigation and lifecycle evidence cover entry from an already-running home document. SEO link.href assignments are canonical/alternate metadata rather than preload. Consent, locale and recovery persistence contain preferences/route state, not selected-file bytes or names. The existing SW handles its own fixed destinations and does not add a U6 file/cache write path.

The broader search also catches existing other-feature workers, result Blob/data previews/downloads, explicit user link/share actions, build-only vendor acquisition and test fixture/control fetches. These are attributed by exact source path and recorded lines, not excluded with a blanket network allowlist. `test-network-review.json` isolates actual test network-name matches. Existing tests' local-server startup probes and Blob-result reads do not become production permissions. SVG local fragment references, PDF `action` dictionaries and variables named `requests` are lexical false positives. Generated office/video/OCR/Python runtimes are physically listed with their owners and are outside the U6 runtime graph; their internals are not newly approved here. Installed PDF.js persistence/network code and actual selected dependency behavior retain the P3 source inventory and production proof. Installed development dependencies, binary WASM internals and Markdown examples are not presented as repository-owned application source.
