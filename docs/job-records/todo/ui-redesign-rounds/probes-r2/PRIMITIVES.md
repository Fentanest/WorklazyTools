# W1a/W1b 정본 삽입용: 7종 프리미티브 계약

현재 v2의 7종 표는 구현 가능한 API 명세까지는 아니다. 아래를 통째로 채택하는 제안이며 기존 Base UI 전체 API 복제를 요구하지 않는다. public 파일 경로·현재 export 이름·모든 실제 소비 props를 보존한다. 코드는 sol, 계획 검토·실험은 astra 역할이다.

## 공통

- CSR React 19. SSR/hydration·중첩 theme·RTL은 범위 밖. 첫 paint는 별도 theme bootstrap의 책임. StrictMode effect 재실행·mount/unmount에는 안전해야 한다.
- 네이티브 button이 기본. `type="button"` 기본값, 소비자의 submit/reset은 보존. button 안 button, anchor 안 anchor 금지. disabled/busy는 mouse·Enter·Space에서 콜백/이동을 0회로 막는다. busy는 `aria-busy=true`, 현재 레이블 보존, spinner `aria-hidden=true`.
- 소비 props를 재귀 스캔해 목록을 저장한 다음 타입을 정의한다. `className`, `style`, native attrs, `aria-*`, `data-*`, `id`, `ref`를 실제 host에 전달. 현재 `render` 소비는 ReactElement(button/a/Link/span)이다. 그 범위로 타입을 닫고 render callback 같은 미사용 Base UI API를 암묵 지원하지 않는다. `nativeButton`은 Switch 실제 소비 때문에 호환 인자로 받되 host DOM에 흘리지 않는다.
- `render`는 cloneElement로 host 하나만 만든다. ref는 element의 ref와 wrapper ref에 모두 전달하고 null cleanup도 전파. className은 내부→render→소비 순서로 `cn`, style도 같은 순서. 필수 role/상태 ARIA/disabled는 사용자 덮어쓰기 불가. handler는 소비 onClick→render onClick→내부 동작 순서, 어느 handler의 defaultPrevented도 내부 동작을 막는다. disabled/busy 가드는 모든 handler보다 먼저. 동일 함수 참조 두 번 호출 금지. onKeyDown도 같은 병합 규칙. 내부 ARIA와 모순된 소비는 타입/테스트에서 잡고 사용자 화면에는 예외를 출력하지 않는다.
- controlled는 관련 value/checked/pressed/open이 undefined가 아닐 때. controlled의 표시 값은 prop만 따르며 요청 callback만 발행한다. 부모가 거절하면 DOM도 이전 값 유지. uncontrolled는 default*를 mount 때 한 번만 읽는다. mount 후 controlled/uncontrolled 전환은 지원하지 않으며 dev 진단만 허용, 사용자용 원시 예외 금지. 프로그램 prop 변경은 change callback 0회. state callback은 사용자 activation당 최대 1회.
- `data-slot` 전부 보존. 상태에 따라 존재하는 `data-checked`/`data-unchecked`/`data-disabled`/`data-open`/`data-closed`, `data-orientation`, `data-size` 등 실제 CSS 소비를 자체 코드/CSS로 소유한다. `shadcn/tailwind.css` 커스텀 변형이 없어도 CSS가 동작해야 한다. 신규 CSS는 opacity로 대비를 깎지 않고 semantic 상태색 사용.
- class-variance-authority, clsx, tailwind-merge, lucide, Tailwind는 유지한다. `use client` 지시문은 CSR에서 기능이 없으므로 자체 파일 정리 시 제거 가능. shadcn CLI/Base UI 의존 종료와 구별한다.

## Sheet 상세

1. 초기 focus: Content의 명시 initialFocusRef → 표시되는 close button → 첫 enabled focusable → dialog(tabIndex=-1). 처음 opening에서만 수행; 단순 rerender/테마 변경 때 재포커스 금지.
2. Tab 집합은 매 keydown 갱신. hidden/display:none/visibility:hidden/inert/disabled/tabIndex<0 제외. 양수 tabindex는 자체 컴포넌트에서 금지. focus된 요소가 사라진 상태도 첫/끝으로 복귀. 마지막→Tab→첫, 첫→Shift+Tab→마지막. 하나면 자신, 0개면 dialog. iframe은 vendor 편집창 내부 Tab을 가로챌 수 없으므로 drawer 안 삽입 제외.
3. 중첩 dialog는 body의 sibling portal. 중앙 modal stack에 등록하여 topmost만 Escape/바깥 pointer 처리. 최상위 닫기 후 부모 opener로 복귀, 부모 배경 inert와 scroll lock 유지. React parent 이벤트 버블링도 stack 검사로 중복 close 차단.
4. backdrop은 `data-slot=sheet-overlay`로 실제 DOM 요소를 dialog 안의 panel과 형제로 배치하고, top-layer 밖 overlay에 클릭 핸들러를 두지 않는다. panel 내부 drag 시작 후 backdrop에서 끝나는 동작은 닫지 않는다. 동일 primary pointer ID로 outside down+outside up을 모두 확인; cancel/lost capture에서는 reset. overlay만 장식이며 dialog의 콘텐츠 폭/높이 측정은 inner panel을 기준으로 한다. native `::backdrop`만 쓰면서 기존 overlay DOM selector가 있다고 주장하지 않는다.
5. native inert에 맡기며 app root에 수동 aria-hidden을 중복 부착하지 않는다. body scroll lock은 참조 횟수0→1 때 이전 inline overflow/paddingRight·scrollY 저장, scrollbar gap 보정; 1→0 때 원값 복원. 기존 style을 빈 문자열로 무조건 덮지 않음. opener가 제거/숨김/inert면 유효한 현재 desktop menu trigger 또는 main(tabIndex=-1)로 복귀.
6. route 변경·820→821 진입은 AppShell이 controlled open=false를 요청. 821→820은 자동 open하지 않음. native close/컴포넌트 unmount/빠른 reopen도 manager에서 1회 정리. route 닫힘의 복귀 대상은 새 main, resize 닫힘은 desktop menu trigger. 부모 unmount는 자식부터 정리; 닫힌 old dialog의 close 이벤트가 새 open을 취소하지 않도록 generation guard. transitionend에만 cleanup을 의존하지 않음.
7. W1b에서는 기존 bottom sheet의 10px 여백·상태 셀렉터·목록 스크롤을 유지해 행동 교체만 검증. W2의 left drawer 전환에서 새 geometry를 적용. native showModal 실패/미지원 환경은 미리 기능검사를 하고 inline navigation을 제공한다(외부 링크/도구 도달 가능, modal/trap 주장 없음); 조용히 빈 메뉴를 띄우거나 원시 예외 노출 금지.
8. W1b 테스트는 controlled parent 거절, 0/1/N focusable, 마지막 동적 제거, disabled 변경, nested Escape/Tab, 기존 body overflow='clip' 복원, route/820↔821, unmount, StrictMode, inside→outside drag, pointer cancel, trigger 제거를 실제 브라우저 이벤트로 포함한다.

## 이번 재현과 구현 게이트의 경계

`NODE_OPTIONS=--max-old-space-size=4096 node /tmp/worklazy-ui-r2/probes/browser.mjs`는 Chromium 152에서 앞/뒤 Tab wrap·nested ESC·native inert·내부 drag·backdrop·0 focusable·focus/scroll 복원·Switch/ToggleGroup 및 검색 계약 일부를 통과했다. standalone prototype이며 React controlled/ref/form/StrictMode/route cleanup의 완성 구현은 아니다. 위의 나머지는 sol의 테스트 fixture에서 **실제 public 컴포넌트를 import**하여 검증해야 한다. 이 HTML DOM을 제품 primitive 대용으로 복사하거나 시험 oracle로 자기 복제하지 않는다.
