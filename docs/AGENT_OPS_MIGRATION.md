# WorklazyTools 에이전트 운영 일치화 — 적용 안내

작성일: 2026-09-22. 기준 저장소: `Fentanest/WorklazyTools`의 `main`, `8552f09015647cea7aabf4d47ff3c206451bc31d`.
이 문서는 파일 적용 안내다. 실제 운영 정책은 PROJECT_RULES.md, 실행은 agent-dispatch-runbook.md, 사용법은 agent-ops-guide.md가 정본이다.

## 덮어쓰기

ZIP에는 프로젝트 루트 기준 경로가 직접 들어 있다. 현재 저장소의 변경을 먼저 백업하고, 해당 저장소 루트에 ZIP의 내용을 **합쳐서** 덮어쓴다. `.agents`와 `.claude`의 숨김 폴더도 포함한다. 압축에 없는 폴더/파일을 지우는 미러 동기화나 `git reset --hard`, `git clean`을 사용하지 않는다. GitHub에 자동 push하지 않는다.

새로운 작업 worktree는 이 변경을 포함한 기준에서 만들거나, 승인된 정확한 사본을 전달한다. 기존 실행은 종료/안전한 인계를 확인하고 새 규칙을 읽게 한다. 문서를 덮어쓴 것만으로 이미 실행 중인 에이전트의 이전 지시가 자동으로 교체되지 않는다. 플러그인 파일·사용자 전역 설정·제품 의존성·API 키는 ZIP에 없다.

## 확정된 운영 변경

- Codex는 설치된 공식 Claude용 플러그인의 companion을 직접 호출한다. codex-rescue.md와 실제 옵션을 참조하지만 LLM 포워더를 다시 실행하지 않는다. 각 worktree에서 발주/상태/결과/취소를 일치시킨다.
- 역할·실행 유형별 쓰기를 분리하고 요청/실제 Codex 세션의 모델·cwd·sandbox를 확인한다. 불일치/미확인 발주를 정상 진행으로 두지 않는다. 기존 전역 권한을 확대하지 않는다.
- Gemini는 `gemini-3.1-pro` 한 모델만 사용한다. 셸·git 읽기·검색·조사 스크립트는 허용하고 비밀값·실주문·운영 상태 변경은 금지한다. 실제 한도 초과에 한해서만 Luna로 조사 대체한다.
- Gemini의 결과 의존 단계는 출력·종료를 회수한 다음 실행한다. 외부 비동기 관리와 회수하지 않은 내부 배경 작업을 구분한다.
- 원문은 Gemini/실행기가 수집해 Jev REST로 대조하고 총괄에는 짧은 판정과 근거 위치만 전달한다. 1차 확인은 정식 기술 검수·필수 검사·최종 승인이 아니다.
- 동일 영역 저위험 미검수 작업 5개 또는 실질 변경 800줄, 영역 전환·고위험·최종 반영이 검수 기준이다. 숫자와 확률 기준은 조정 가능한 초기값이지 실측 최적값이 아니다. 시간 경과·모델 교체만으로 검수를 발주하지 않는다.
- 작업 브랜치의 보존용 커밋과 정식 통합/배포 승인을 분리한다. 검수 후보는 고정하고 A+B 검수 중 C는 대기로 남긴다. 중복 발주와 불명확한 재시도는 원장·잠금으로 막는다.

Muse/OpenCode는 WorklazyTools에만 남겼다. 같은 worktree 세션 재개·분기, 다른 worktree의 새 세션/인계, stdin 차단 절차를 유지한다. 게시 체크리스트의 전체 목록은 최초 공개·광범위 변경용이며 일반 변경에는 영향 범위만 적용한다.

## 실행 확인

사용자는 `TYPESAFE_API_KEY`를 Linux 터미널에 이미 export했다. 그 터미널에서 아래 명령을 실행한다. 키를 다시 문서·프롬프트·명령 인자에 적지 않는다. 이미 다른 셸에서 실행 중이던 에이전트는 나중에 export한 값을 자동으로 받지 않는다.

```bash
python3 -m unittest discover -s tests/agent_ops -v
python3 scripts/agent_ops.py doctor --live
python3 scripts/codex_direct.py doctor
```

첫 명령은 과금 없는 모의·로컬 검사다. 두 번째는 실제 TypeSafe 계정으로 합성 입력을 보내는 소규모 API 호출이며 저장소 코드는 보내지 않는다. 세 번째는 설치된 companion의 계약·상태 경로 확인이며 Codex 모델 잡을 발주하지 않는다. 출력에 키 값이 나오지 않는다.

발주용 Node와 기존 공식 Codex 플러그인, 기존 agy, Python 3.10+와 git이 필요하다. Python 패키지 추가 설치는 없다. 플러그인 경로가 여러 개이면 확인된 설치 경로를 `--plugin-root`로 지정한다. 실제 worktree의 신뢰/캐시/임시 쓰기 준비는 호스트 담당이 확인한다.

## 동작 범위와 확인되지 않은 것

실제 HTTP 클라이언트와 companion subprocess 호출 코드를 포함했다. 준비된 검수 worktree가 있으면 `check --dispatch`가 판정에 따라 실제 검수 잡을 발주한다. 준비 없이 다른 작업 공간을 바꾸거나 자동 reset하지 않는다. 스크립트 옵션과 입력 형식은 agent-ops-guide.md와 samples를 따른다.

이 ZIP은 전역 Stop hook·상주 daemon을 설치하지 않는다. 작업 종료/영역 전환 시 규칙에 따라 실행기가 명령을 호출해야 한다. 키가 존재한다고 모든 단계가 저절로 실행되는 것은 아니다. 별도 사전 계획·현재 역할·승인 범위를 생략하지 않는다.

생성 환경에서는 사용자의 Linux 셸 환경변수와 설치된 Codex/agy에 접근하지 못했다. 따라서 사용자 계정의 실제 Jev 인증 성공, 실제 모델 판단 정확도, 호스트 플러그인·agy 권한/가용성은 여기서 실측하지 않았다. 제공 단위 테스트는 API 응답 구조·실패 경계·Git 상태·모의 companion subprocess를 검사하며 제품 전체 회귀나 실주문 검사는 실행하지 않는다.

비밀 경로/패턴 차단은 추가 방어이지 모든 민감정보 탐지의 보증은 아니다. 승인된 소스·요구사항·비식별 증거만 전송한다. 원문 선택·테스트 의존 관계의 완전성과 수집 누락은 정식 검수에서도 확인한다. 미확정 발주 예약은 자동 삭제/재발주하지 말고 기존 잡/프로세스/산출물과 대조해 복구한다.

## 변경 파일과 무결성

`agent-ops-manifest.json`에 배포 파일별 SHA-256·크기와 기준 커밋이 있다. 이 목록은 덮어쓸/추가할 파일 목록이며 기존 저장소 전체 목록이 아니다. manifest 자신은 해시 목록에서 제외한다. 사용자 환경에서 이 파일들을 변경하면 그만큼 해시가 달라지는 것이 정상이다.
