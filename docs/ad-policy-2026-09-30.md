## 구현 순서

1. 단일 공개 여부와 문서 준비 상태 계약을 만들고, 광고와 방문 분석의 적격성을 별도로 판단한다.
2. 광고 목적 재로드를 제거한다. 격리·초기화 문서 이동은 유지하고 최초 광고·분석 요청이 최종 문서보다 앞서지 않게 한다.
3. GA는 고정 경로 allowlist와 고정 제목으로 수동 pageview를 보내고, 중복 자동 History 측정은 운영 설정으로 명시한다. Naver SDK가 실제 URL/제목을 자체 읽으므로 민감 쿼리 보호를 실제 전송으로 검증한다.
4. 비디오 공개 경로·정적 출력·탐색 경로를 막고, 기존 서비스워커 범위만 정리한다.
5. 개인정보·동의 버전을 새 광고 사업자에 맞춰 개정하고 한·영 안내를 맞춘다. 쿠팡 변경을 최종 후보에서 읽어 슬롯·동의·CSP 충돌을 통합한다.
6. 정적·단위·브라우저·격리 기능 검사를 실행하고 공급자 실동작과 계정 설정은 별도 기록한다.

## 기술 검토 보완(2026-09-30, Astra)

- 공개 적격성, 문서 준비, 광고 적격성, 방문 분석 적격성을 분리한다. 준비·이동 전에는 어느 공급자도 요청하지 않으며, 오류 화면 광고 차단을 안전한 오류 통계의 도구별 영구 차단으로 쓰지 않는다.
- Auto ads는 삽입 뒤 script 제거만으로 중단되지 않는다. 동의 철회·오류·라우트 변경의 후속 요청을 실제 확인하고, 제어 불가능하면 직접 슬롯 설정과 콘솔 제외를 운영 확인 항목으로 남긴다.
- GA/Naver는 원본 URL·query·hash·제목·referrer와 대기 이벤트를 그대로 보내지 않는다. 전송 직전 동의·문서 세대·허용 경로를 검사하고 저장소 불가 시에도 동작하는 동의 버전을 둔다.
- Redactor CSP는 공급자별 실제 필요 출처만 허용하며, Office/XLS의 COEP·SharedArrayBuffer 및 최초 서비스워커 재로드는 보존한다. 로더 성공과 후속 광고 표시를 구분해 재현한다.
- 비디오 비공개는 카탈로그뿐 아니라 라우트·별칭·정적 생성·검색·저장 목록·이전 서비스워커 범위까지 확인한다. 쿠팡은 별도 구현을 통합하되 HWP 집중 화면 배치와 반응형 재요청을 확인한다.
- 필수 증거는 일반→PDF→격리 문서 이동, 철회 중 지연 응답, 민감 sentinel, 비디오 직접 진입, 파일 출력 회귀, 모바일 집중 편집을 포함한다. `build`, `test:unit`, `test:static`, `test:ads`, `test:office`, `test:xls-preserve`, `test:xls-first-load`에서 영향 검사를 고른다.

## 확인한 공급자 제약

- AdSense는 자동 재로드 페이지의 광고, 오해를 부르는 조작부 주변 광고를 제한한다. 임의 iframe 안의 AdSense 삽입도 공식 FAQ상 금지이므로 iframe을 임시 우회책으로 쓰지 않는다.
- GA `send_page_view:false`만으로 향상된 측정의 History pageview가 꺼지지 않는다. 운영 GA4 데이터 스트림의 해당 옵션을 별도 확인해야 한다.
- 현재 Naver `wcslog.js`는 `location.href`, `document.title`, `document.referrer`를 직접 읽는다. 지원 근거 없는 옵션으로 개인정보 차단을 주장하지 않는다.
- COEP `require-corp`에서 제3자 후속 리소스가 거절될 수 있다. 로더 script 성공과 실제 광고 노출, 문서 편집·내보내기 성공을 분리해 기록한다.

- 최종 빌드 뒤 `npm run test:unit` 652/652, `npm run test:static` 158개, 직접 진입 감사가 다시 통과했다. `npm run test:utilities`는 **실패**로 남겼다. 모바일 390×844에서 시트 패널 실측 x=10, y=20, width=390, bottom=844로 오른쪽 10px 넘침과 하단 여백 부족이 재현되어 `tests/utility-tools-smoke.mjs:188`의 비중첩 기하 검사가 시간 초과됐다. 광고·분석 모의 공급자·언어 선택·도구 목록 단계는 통과했으며, 이 모바일 시트 문제를 테스트 약화나 skip으로 숨기지 않는다. 패널 CSS 수정과 별도 회귀 검사가 후속 필요하다.

## 운영·실동작 미확인

- AdSense Auto Ads는 초기 스크립트를 한 번 넣는 기반이다. 실제 광고 노출·계정 승인·콘솔 페이지 제외 해제, 모바일 앵커와 도구 조작부의 중첩, 동의 철회 뒤 이미 로드된 Auto Ads의 후속 요청 완전 중단은 코드/모의 공급자만으로 증명되지 않았다. 직접 슬롯을 쓰려면 실제 광고 단위 ID와 운영 결정이 필요하다.
- Redactor CSP와 Office/XLS COEP에서 GA·Naver·AdSense·쿠팡의 **실제 후속 iframe·리소스·집계** 및 사용자의 편집·저장 동시 성공은 모의 공급자 검사만으로 확인되지 않는다. 특정 공급자의 실제 차단은 재현되지 않았으며, 반대로 실호환 완료라고도 보지 않는다.
- 쿠팡 위젯은 별도 iframe이지만 GA·Naver·AdSense 진입 스크립트는 일반 도구 문서의 전역 JavaScript 권한으로 실행된다. 서비스 코드가 파일명·본문·결과를 공급자 이벤트나 URL에 넣지 않는 것과, 공급자 코드가 DOM·File 객체에 기술적으로 접근할 수 없다는 것은 다른 주장이다. 후자는 현재 구조에서 보장되지 않으며 엄격한 제3자 접근 격리는 별도 출처/문서 구조와 공급자 동작 검증이 필요하다.
- GA4 향상된 측정의 자동 History·검색·양식·다운로드 설정, AdSense 자동 광고 형식·과거 페이지 제외, 쿠팡 계정 승인·고지 문구, 지역별 CMP, Naver SDK의 실제 집계값은 운영자 콘솔에서 확인해야 한다. 쿠팡 공식 포털은 로그인 전 공개 정책 본문을 확인할 수 없어서 사용자가 지정한 한국어 고지를 유지했다. 공급자 실운영 요청/클릭·구매는 자동화하지 않았다.
