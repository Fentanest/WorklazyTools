## 구현 순서

1. 단일 공개 여부와 문서 준비 상태 계약을 만들고, 광고와 방문 분석의 적격성을 별도로 판단한다.
2. 광고 목적 재로드를 제거한다. 격리·초기화 문서 이동은 유지하고 최초 광고·분석 요청이 최종 문서보다 앞서지 않게 한다.
3. GA는 고정 경로 allowlist와 고정 제목으로 수동 pageview를 보내고, 중복 자동 History 측정은 운영 설정으로 명시한다. Naver SDK가 실제 URL/제목을 자체 읽으므로 민감 쿼리 보호를 실제 전송으로 검증한다.
4. 비디오 공개 경로·정적 출력·탐색 경로를 막고, 기존 서비스워커 범위만 정리한다.
5. 개인정보·동의 버전을 새 광고 사업자에 맞춰 개정하고 한·영 안내를 맞춘다. 쿠팡 변경을 최종 후보에서 읽어 슬롯·동의·CSP 충돌을 통합한다.
6. 정적·단위·브라우저·격리 기능 검사를 실행하고 공급자 실동작과 계정 설정은 별도 기록한다.

## 확인한 공급자 제약

- AdSense는 자동 재로드 페이지의 광고, 오해를 부르는 조작부 주변 광고를 제한한다. 임의 iframe 안의 AdSense 삽입도 공식 FAQ상 금지이므로 iframe을 임시 우회책으로 쓰지 않는다.
- GA `send_page_view:false`만으로 향상된 측정의 History pageview가 꺼지지 않는다. 운영 GA4 데이터 스트림의 해당 옵션을 별도 확인해야 한다.
- 현재 Naver `wcslog.js`는 `location.href`, `document.title`, `document.referrer`를 직접 읽는다. 지원 근거 없는 옵션으로 개인정보 차단을 주장하지 않는다.
- COEP `require-corp`에서 제3자 후속 리소스가 거절될 수 있다. 로더 script 성공과 실제 광고 노출, 문서 편집·내보내기 성공을 분리해 기록한다.
