# Stirling page layout port for PDF document conversion

Source: `Stirling-Office-Convert` release `0.2.2`, commit `673aab8d6ac784524cd1d90141c95e74b9fd26ae`, used by the checked Stirling-PDF checkout at `973bff865`. The implementation below is connected to the active PPTX/HWPX conversion client, not a standalone copy.

| Upstream source | Worklazy implementation | Adaptation |
| --- | --- | --- |
| `core/src/main/java/stirling/software/officeconvert/extract/{PageData,Glyph,FontInfo}.java` | `src/features/pdf-editor/stirlingLayout.ts` | TypeScript page, glyph and font records; PDF.js viewport coordinates replace PDFBox. |
| `core/src/main/java/stirling/software/officeconvert/layout/{LineBuilder,ParagraphBuilder}.java` | `src/features/pdf-editor/stirlingLayout.ts` | Row/segment spacing and paragraph pitch/look thresholds retained for text frame placement. Java's larger word/column/table pipeline is not yet ported. |
| `core/src/main/java/stirling/software/officeconvert/slides/{Slide,Frame,PictureShape,SlideBuilder,PageFit}.java` | `src/features/pdf-editor/stirlingLayout.ts`, `stirlingPageFit.ts` | Page and shape model, paint ordering and page fitting feed PptxGenJS and the existing HWPX SDK. |
| `core/src/main/java/stirling/software/officeconvert/model/{Paragraph,Picture,RunStyle}.java` | `src/features/pdf-editor/stirlingLayout.ts` | Only fields consumed by the browser writers are represented. |
| PDFBox `PageReader`/`GlyphCollector` | `src/features/pdf-editor/stirlingPdfAdapter.ts` | PDF.js text transforms, CropBox/rotation-aware viewport, image operation CTMs and decoded bitmaps. PDF.js 6's fused `constructPath` enables a text-free graphics background for routine vector tables while text remains editable. |
| Java `PptxWriter` | `src/features/pdf-editor/stirlingDocument.worker.ts` | Existing PptxGenJS OOXML writer consumes the ported slide model; Java streams and temp files are not used. The PDF.js adapter keeps image placement bounds even when vector paint requires a graphics background and therefore skips bitmap extraction. This lets the same page still detect a full scan backdrop, hidden OCR and text/image overlap. Negative diagonal image transforms (including 180° rotations), reflected transforms, and filled vector paths painted over visible text use complete-page fallback. Ordinary stroked table grids remain in the text-free graphics background with separately editable text.

`stirlingDocumentClient.ts` queues conversions on one Worker, reuses its loaded runtime across sequential files, and terminates it on cancellation, five-minute operation timeout or writer failure. `releaseStirlingDocumentSession()` immediately rejects active/queued work and releases the Worker at batch end; an unclaimed idle Worker exits after 60 seconds. The Worker analyzes the PDF and writes the output, so cancellation interrupts both phases. `pdfPageImageDocument.ts` passes encoded page Blobs to the same writer. This keeps JPEG pages out of main-thread Base64 arrays and uses the original page ratio for each slide/HWPX image. Editable extraction has a 12-megapixel single-image threshold, a 12-megapixel page-render budget and a separate 96-MiB retained-image budget.

Known limits in this port: PDF.js text content does not expose all PDFBox glyph styling, exact text colors or reliable visibility for every hidden-text method. Image-preserved fallback pages keep visible content but do not offer editable text. The port does not yet perform Stirling's table-cell inference or multi-column analysis; routine vector table lines are flattened behind editable text. Text-note annotations are painted using the geometry of PDF.js's note icon, while their interactive note content is not exported. PptxGenJS places bitmap images and editable text; HWPX uses text boxes for positioned text but font substitution can change glyph metrics. These outputs should be described with those limits rather than as exact editable reconstructions.

Focused verification: `npx tsc -b --pretty false`, `npx vite build`, `node tests/pdf-stirling-layout-smoke.mjs`, and `STIRLING_NATIVE_RENDER=1 node tests/pdf-stirling-layout-smoke.mjs` (Vite on port 4273). The browser test reopens PPTX/HWPX ZIP content and checks reversed Korean/English text order, embedded pictures, page positions, a scan page bitmap in both outputs, a generated invisible OCR layer plus visible title/vector stamp/text-note annotation, nonblank rotated page, asymmetric rotated/reflected/clipped pictures, 180° image rotation, opaque overpaint that hides earlier text, a vector before full-scan image, opposite text/image paint orders, vector graphics with editable text, Worker reuse, timeout, disposal, in-flight cancellation and retry. Native mode renders PPTX through LibreOffice and HWPX through the SDK's `renderPageSvg()`, then checks pixel content. The HWPX writer reopens each result through `@rhwp/core`; the rich two-page fixture now renders as two physical pages with source text, table borders, image and footer on the matching page.
