# 변경 범위 기반 검증

역할·승인·1차/정식 검수·누적 상한·종료의 정본은 [PROJECT_RULES.md](../../../PROJECT_RULES.md)다. 명령을 찾는 안내는 [검사 경로](../../../docs/verification-guide.md), 상태·Jev 연결은 [운영 도구 안내](../../../docs/agent-ops-guide.md)다. 이 스킬에서 정책을 복제·재정의하지 않는다.

## 실제 절차

1. 맡은 역할과 지시서의 목표·제외·완료 기준·실제 대상 소스를 확인한다. staged·unstaged·필요한 새 파일을 포함하며 HEAD 동일만으로 같다고 보지 않는다.
2. 변경에서 직접 호출·상태·소비자·공유 계약·출력/저장 형식·생성기·의존성으로 이어지는 관계를 찾는다. 파일 수나 줄 수만으로 영향 범위를 단정하지 않는다.
3. 검사별로 새 실행/재사용/최종 이월/대상 아님을 구분한다. 실제 명령·필터·선택 건수·현재 소스·환경·증거를 확인한다. 0건·미실행·중단·오래된 빌드를 통과로 표시하지 않는다.
4. 구현자는 국소 검사와 원문 증거를 남긴다. Gemini/Jev의 1차 대조 뒤 검수 대기로 누적한다. 보존용 커밋마다 정식 검수를 요구하지 않는다.
5. Astra는 고정된 묶음의 전체 요구사항·diff·증거 적정성·필수 누락을 확인하고 고위험·이상 징후·대표 경로만 필요한 독립 재현을 한다. Jev 의심 부분만 보는 것으로 검수를 제한하지 않는다.
6. 추가 수정·입력·환경 변화로 무효가 된 결과만 갱신한다. 통합 후보에서는 실제 공유 계약·연결·충돌 해결 영향과 최종 필수 검사를 회수한다. 개별 브랜치 통과를 통합 통과로 쓰지 않는다.
7. 시각 검토는 영향 있는 조합을 선정해 실제 열람한다. 캡처·픽셀 비교만으로 열람을 대신하지 않는다. 민감 입력은 합성·비식별 자료로 대체한다.

## 기록·종료

기존 작업 기록에 대상·처리 상태·명령·결과·원본 증거를 연결한다. 로그 전문·정상 결과·공통 규칙을 반복하지 않는다. 미확인 필수 항목과 차단 쟁점을 남기며 목표·기대값을 낮춰 통과시키지 않는다. 검수 통과·Claude 최종 판정·배포는 서로 다르다. plan-only의 정상 종료는 정본화·구현 대기다. 이 스킬은 새 구현·배포·전역 권한 변경을 승인하지 않는다.
