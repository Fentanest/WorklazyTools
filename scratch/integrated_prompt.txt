WorklazyTools — 기존 추가 원고 보존 + 검색어·페이지 설계 통합 반영
대상 저장소: Fentanest/WorklazyTools

이번 작업은 앞서 전달한 원고를 폐기하거나 SEO 문장으로 전면 교체하는 작업이 아니다.
기존 원고의 설명·예시·주의사항을 보존하면서, 각 페이지가 담당할 검색 의도에 맞춰
검색 제목·화면 제목·소개문·소제목·FAQ·관련 도구 링크·정적 출력을 연결하는 후속 작업이다.

이전에 원고를 이미 전달받았으므로, 적용 상태부터 확인하고 필요한 차이만 수정한다.
“이미 전달됨”을 “모두 구현·검증됨”으로 간주하지도 말고, 아직 적용하지 않았다고 가정해 중복 삽입하지도 않는다.
계획서를 다시 제출하고 기다리기만 하지 말고, 아래에서 확정된 범위는 실제 수정과 검증까지 진행한다.

==================================================
0. 자료의 역할과 작업 범위
==================================================

이 통합 문서의 부록 A:
WorklazyTools_도구별_페이지별_추가원고.md 전문.
23개 도구의 설명·예시·FAQ, 세부 경로와 공통 페이지 문구를 담은 콘텐츠 원안이다.

이 통합 문서의 부록 B:
WorklazyTools_검색어_페이지맵_초안.md 전문.
기존 44개 도구 경로의 검색 의도·제목 후보·담당 URL·제외할 의도를 담은 편집 설계표다.
신규 URL 44개를 생성하라는 뜻이 아니다.

별도로 받은 동일 제목 JSON은 부록 B의 구조화 참고자료다.
있다면 대조하되, 없는 것을 이유로 작업을 중단하지 않는다.
JSON을 새로운 런타임 설정으로 그대로 복사할 필요는 없다.

역할을 혼동하지 않는다.
- 부록 A: 사용자가 이해하고 실제 작업하는 데 필요한 설명의 기반.
- 부록 B: 그 설명을 어떤 검색 목적·페이지·제목으로 연결할지 정하는 기준.
- 현재 코드와 검증 결과: 실제 지원 형식·옵션·동작을 확인하는 근거.
- 이 본문: 이미 진행된 작업을 보존하며 두 자료를 통합하는 실행 지시.

두 부록은 작성 당시의 코드 판독과 제안이다.
부록 A의 4451301, 부록 B의 00d95ef는 원고 작성 기준이지 checkout/reset 대상이 아니다.
현재 작업 브랜치·HEAD·미커밋 변경과 실제 최신 main의 차이를 먼저 확인한다.
이미 해결된 문제를 옛 판독 문장만 보고 다시 고치지 않는다.

이번 범위의 콘텐츠·번역·SEO 메타데이터·가이드 연결·정적 생성·관련 검증 수정은 승인한다.
사용자 미커밋 변경을 지우거나 되돌리지 않는다.
별도 승인 없이 commit/push/배포/의존성 추가/전체 브랜치 변경을 하지 않는다.

PDF 렌더러·의존성 패치, 오피스 자동 시작·드롭·집중 모드, HWP 실행,
전역 상단바, 네 테마와 아이콘 팔레트, 파일 처리 엔진, 암호·격리·광고 동의 정책은 보존한다.
원고와 기능이 다르다고 콘텐츠 작업을 빌미로 처리 엔진까지 바꾸지 않는다.
확인된 현재 동작에 맞춰 필요한 문구만 조정하고, 변경 이유를 기록한다.
아직 구현되지 않은 기능을 지원한다고 쓰거나, 사용자가 요청한 기능을 미지원 문구로 덮어 완료 처리하지 않는다.

==================================================
1. 이미 반영한 원고를 먼저 대조한다
==================================================

현재 라우터·도구 목록·언어 지원·가이드·메타데이터·정적 생성기를 읽는다.
부록 A의 각 도구/공통 페이지/세부 경로와 현재 화면 원고를 대조한다.

페이지별 작업표를 만든다.
- 실제 경로와 언어
- toolId와 실제 guideKey
- 이전 원고의 해당 절
- 현재 반영 상태: 미반영 / 일부 반영 / 반영 완료 / 의도적 제외
- 담당 검색 의도와 대표 검색어 후보
- 바꿀 title/H1/소개문/소제목/FAQ/내부 링크
- 유지할 예제·제약·안전 안내
- canonical·정적 출력·검증 상태

이미 잘 적용된 본문은 유지한다.
동일한 의미의 문단·FAQ를 다시 추가하지 않는다.
중복을 합칠 때에도 고유한 지원 제한이나 예시가 사라지지 않게 한다.
부록의 “보강 방향·반영 전 확인·검토 기준·우선순위·편집 확인”은 내부 지시다.
이 문구와 출처 목록 전체를 사용자 페이지에 그대로 게시하지 않는다.
“게시용 추가 원고” 안에도 검증 지시가 섞인 부분은 사용자 설명과 분리한다.

이번에는 README만 바꾸거나 docs에 계획만 저장하고 끝내지 않는다.
사용자가 방문하는 실제 도구 페이지에 반영해야 한다.

==================================================
2. 검색어는 후보로 관리하고, 작업 범위를 정확하게 유지한다
==================================================

대표 검색어 / 동의어 / 관련 세부 작업 / 본문에서 답할 질문 /
이용 조건 표현 / 목표에서 제외할 의도를 구분한다.
대표 검색어 하나를 정했다고 나머지 기능 설명을 삭제하지 않는다.
후보 검색량·경쟁도·순위·CTR을 조사한 것처럼 꾸미지 않는다.
모르는 수치는 null 또는 미측정으로 둔다. P1/P2/P3는 편집 우선순위다.

기본 도구 23개의 대표 후보는 다음과 같다.

excel-merger        : 엑셀 파일 합치기
excel-compare       : 엑셀 파일 비교
excel-cleaner       : 엑셀 데이터 정리
document-generator  : 워드 문서 일괄 생성
document-compare    : 워드 문서 비교 — 한글 문서 비교도 같은 페이지의 별도 지원 범위로 유지
pdf-compare         : PDF 파일 비교
pdf-editor          : PDF 페이지 편집
hwp-editor          : 한글 파일 편집
office-editor       : 온라인 문서 편집
video-studio        : 온라인 동영상 편집
audio-studio        : 온라인 오디오 편집
image-studio        : 온라인 사진 편집
text-merger         : 텍스트 파일 합치기
text-tools          : 텍스트 줄바꿈 제거 — 공백·중복 줄·표기 변환도 유지
text-formatter      : JSON 정렬 — SQL·XML 형식화 설명도 유지
work-calculator     : 영업일 계산기 — 연차는 별도의 계산 목적임을 설명
timezone-calculator : 시차 계산기
payroll-calculator  : 월급 실수령액 계산기 — 주휴수당·퇴직금도 별도 계산으로 유지
document-redactor   : PDF 개인정보 가리기
image-privacy       : 사진 위치정보 삭제
security-tools      : 비밀번호 생성기
qr-studio           : QR 코드 만들기 — QR 읽기·스캔 설명도 유지
data-converter      : CSV JSON 변환 — 반대 방향과 HTML 표 변환도 유지

동의어·세부 경로·제목 후보·제외 의도는 부록 B의 전체 44개 항목을 사용한다.
현재 경로가 추가·변경됐다면 누락을 조사하되, 이를 핑계로 새 URL을 양산하지 않는다.

예시:
- PDF 합치기/병합/여러 PDF 하나로: 기존 merge 경로 하나에 자연스럽게 묶는다.
- PDF 합치기와 OCR: 다른 작업이므로 각각의 기존 경로가 담당한다.
- QR 한 개 만들기와 엑셀 목록으로 일괄 생성: 기본 경로와 bulk를 구분한다.
- PDF 워드 변환과 PDF 엑셀 변환: 다른 목적이지만 현재 convert 화면에서 각각 설명할 수 있다.

금지:
동의어·띄어쓰기·확장자·도시·연도만 바꾼 중복 페이지 생성,
대표 검색어만 남기고 도구의 다른 실제 기능을 숨김,
meta keywords·숨은 본문·키워드 나열 문단으로 완료 처리,
검색어 때문에 기능을 과장하거나 미지원 작업을 홍보하는 것.

==================================================
3. 원고를 검색 의도에 맞게 다듬되 내용과 자연스러움을 보존한다
==================================================

페이지별로 다음을 함께 정리한다.
- 메뉴명: 짧고 일관되게.
- title: 실제 수행할 작업을 알 수 있게.
- H1: 사용자가 화면에 들어와 알아볼 수 있게.
- description/첫 소개: 입력·결과·중요 조건을 평이하게.
- H2/H3: 사용자가 묻는 질문과 옵션 선택 기준을 중심으로.
- 예시: 준비물 → 선택 → 예상 결과 → 확인할 것.
- FAQ: 다른 절에서 답하지 못한 실제 질문을 보완.
- 관련 도구: 작업의 다음 단계나 혼동하기 쉬운 다른 작업을 연결.

title/H1/메뉴를 기계적으로 같은 문자열로 만들지 않는다.
반대로 서로 다른 기능처럼 보이게 이름을 바꾸지도 않는다.
브랜드 접미사·구분자를 일관되게 사용하되 제목 길이 숫자를 합격 기준으로 만들지 않는다.
첫 화면에서 도구 제목을 하나로 식별할 수 있게 하며 초기 HTML과 실행 후 H1이 어긋나지 않게 한다.

“부서별 엑셀 자료 합치기로 취합할 때”는
“부서별 엑셀 자료를 하나로 합칠 때”처럼 자연스럽게 쓴다.
정확한 검색어 문자열을 모든 문장에 반복하지 않는다.

기존의 쉬운 문장, 구체적인 주의사항, 입력→출력 예제를
짧고 상투적인 SEO 문장으로 교체하지 않는다.
“무료·설치 없음·로컬 처리”만 반복해 분량을 늘리지 않는다.
페이지마다 동일한 글자 수나 FAQ 수를 채우지 않는다.
검색 노출·순위·유입량·AdSense 승인을 보장하는 문장을 쓰지 않는다.

아래는 통합 방법의 구체 예시다. 다른 도구도 같은 방식으로 편집한다.

[엑셀 병합]
메뉴: 엑셀 병합
제목: 엑셀 파일 합치기·시트 병합 | Worklazy Tools
H1: 엑셀 파일·시트 합치기
소개: 여러 엑셀·CSV 파일을 하나의 XLSX로 합칩니다. 시트별로 모으거나 데이터를 세로·가로로 이어 붙일 수 있습니다.
소제목: 여러 시트를 한 파일로 모으기와 한 시트로 합치기는 어떻게 다른가요?
본문: 부록 A의 시트별/세로/가로 선택 설명과 작은 결과 예시를 보존한다.
필수 제한: 가로 병합은 사번·고객번호로 자동 연결하는 기능이 아님. 수식·서식·매크로 범위 보존.
관련 링크: 수정 전후 엑셀 비교 / 공백·중복 데이터 정리.

[워드 일괄 생성]
메뉴: 워드 일괄 생성 — 다시 ‘메일머지’로만 바꾸지 않는다.
제목: 워드 문서 일괄 생성 - 엑셀 명단으로 메일머지 | Worklazy Tools
소제목: 엑셀 명단으로 이름이 다른 안내문을 한 번에 만들려면?
본문: DOCX의 {이름}·{부서} → 엑셀 목록 → 열 연결 → 문서 한 개 시험 → 전체 생성 순서를 유지한다.
단순 설명으로 줄이거나 준비 단계를 삭제하지 않는다.
필수 제한: 이메일 발송·AI 글쓰기 아님. 단순 변수와 실제 지원 범위 유지.

[PDF 비교]
제목: PDF 파일 비교 - 화면·텍스트 변경사항 확인 | Worklazy Tools
소제목: 수정본에 표지가 추가되면 어느 페이지끼리 비교해야 하나요?
본문: 부록 A의 페이지 대응 예시와 화면/텍스트 비교 차이를 유지한다.
추가 질문: 스캔 PDF의 텍스트 결과가 비면 내용이 없는 건가요?
필수 제한: 텍스트 없음은 내용 동일 판정이 아니며 자동 OCR·동일성 보장을 추가하지 않는다.

[사진 메타데이터 제거]
메뉴: 사진 메타데이터 제거 — 기능명은 유지한다.
제목: 사진 위치정보 삭제 - EXIF·GPS 확인 및 제거 | Worklazy Tools
소제목: 촬영정보를 지우면 사진에 보이는 주소도 없어지나요?
본문: 부록 A의 보이는 정보/숨은 정보 구분, 결과 방향·화질 확인을 유지한다.
필수 제한: 얼굴·주소 자동 가리기 아님. 실제 지원 형식을 확인하고 HEIC 미지원 안내를 보존한다.

[QR 일괄 생성]
제목: QR 코드 일괄 생성 - 엑셀·CSV로 대량 생성 | Worklazy Tools
소제목: 엑셀 목록의 한 행을 QR 코드 한 개로 만들기
본문: 내용 열 → 파일명 → QR → 인쇄 라벨 예시를 연결한다.
필수 제한: 최종 PNG 재판독과 인쇄물에서의 판독 검증을 구분한다. 방문 통계·동적 주소 관리를 약속하지 않는다.

==================================================
4. 검색어 때문에 잘못된 기능 기대를 만들지 않는다
==================================================

부록 B의 excludedIntentsOrClaims에 해당하는 의도는 제목과 홍보에서 제외한다.
단, 왜 다른 도구를 써야 하는지 설명하는 FAQ에서 언급하는 것은 가능하다.
이 항목은 검색엔진 차단 목록이나 광고 제외 키워드가 아니다.

특히 다음을 지킨다.
- PDF 분할: 페이지를 나누거나 추출하는 것. 여백 크롭을 지원한다고 쓰지 않는다.
- PDF 도장: 도장·서명 이미지 삽입. 인증 전자서명이나 전자계약으로 홍보하지 않는다.
- 영상 음원 추출: 사용자가 선택한 영상 파일 처리. 유튜브 URL 다운로드로 유도하지 않는다.
- 개인정보 가리기: 직접 영역 선택. 자동 탐지나 완전한 유출 방지를 보장하지 않는다.
- 이미지 리사이즈: 크기 변경. AI 화질 복원이나 특정 KB 이하 결과를 보장하지 않는다.
- 문서 비교: Word끼리/HWP끼리의 범위를 유지한다.
- 급여·연차: 실제 적용 기준 확인 없이 ‘최신·정확한 법정 정산’ 문구를 넣지 않는다.
- 포맷터: 형식 정리와 SQL 실행·DB 검증을 구분한다.

현재 지원이 실제로 바뀌었다면 구현·테스트 근거와 문구 변경 이유를 함께 기록한다.
부록의 옛 제한을 무조건 정답으로 반복하지도 않고, 근거 없이 삭제하지도 않는다.

==================================================
5. 원고를 놓을 위치와 작업 화면을 구분한다
==================================================

도구 상단: 결과와 준비물 중심의 짧은 소개.
옵션 옆: 사용자가 선택해야 하는 이유와 주의점.
작업 영역 아래: 상세 예제·결과 검토·고유 FAQ·관련 도구.
홈: 기존 11개 도구 배치와 ‘바로 사용할 도구’ 제목을 유지하며 사례 설명을 보강.
전체 도구: 병합/비교/정리, 보이는 정보/메타데이터 등 선택 비교를 보강.
About/Contact/Privacy/Terms/Licenses: 부록 A의 해당 문구를 역할에 맞춰 반영.

집중 편집 화면, 로딩·오류·세션 의존 결과 화면에는 SEO 장문을 끼워 넣지 않는다.
현재 단계·다음 행동·저장·복구 안내와 전체 사용법 접근 경로만 유지한다.
드롭 카드·파일 선택·저장 버튼·문서 캔버스를 아래로 밀거나 덮지 않는다.
상세 원고 때문에 넓은 작업 영역이나 네 테마를 다시 설계하지 않는다.

접기/펼치기를 사용하더라도 사용자가 접근할 수 있는 실제 본문이어야 한다.
검색엔진용 숨은 텍스트, 봇에게만 다른 원고, JSON-LD에만 있는 FAQ를 만들지 않는다.

공개 업무 문서·현재 대화의 계약서·연락처·주소·사용자 파일·암호는 샘플로 쓰지 않는다.
다운로드 예제를 추가하려면 가상 데이터로 만들고 실제 도구 결과와 대조한다.
실물 파일을 만들거나 결과를 검증하지 않았다면 다운로드 링크·완성 사례로 표시하지 않는다.
숫자·날짜·파일명 예시는 가상 예시라는 점을 분명하게 한다.

==================================================
6. 단일 원고에서 실제 화면과 정적 출력을 연결한다
==================================================

현재 사용 중인 guide resolver와 스키마를 먼저 재사용한다.
검색 기획표를 또 하나의 사용자 원고 저장소로 만들지 않는다.
상세 설명·예제·FAQ의 언어별 정본은 하나로 유지한다.
검색 의도 기획과 실행 원고가 다른 역할이라는 점은 유지한다.

모든 경로에서 다음 관계를 명시적으로 연결한다.
경로/언어 → toolId → guideKey → 공통 블록+경로별 블록/FAQ IDs → 출력.

excel-merger와 excel, video-studio와 video.page,
pdf-editor와 pdfEditor.standard/pdfEditor.convert처럼 서로 다른 식별자를 혼동하지 않는다.
하이픈을 없애거나 점으로 나누는 추측 로직으로 가이드 키를 만들지 않는다.
이미 올바른 공통 연결이 있다면 그것을 확장하고 중복 맵을 만들지 않는다.

확인 대상 예시(실제 현재 구조를 우선한다):
- src/app/seo.ts
- src/locales/{ko,en}/tools.json, features.json, guides.json, pages.json
- 가이드 데이터 모듈·훅·ToolGuideWrapper·ToolGuide
- scripts/generate-static-pages.mjs
- 가이드/i18n/static 검증과 배포 워크플로

정적 생성기는 메타 설명·기능 목록·FAQ뿐 아니라
공개 상세 안내에 필요한 blocks와 검증된 예시도 초기 HTML에 포함하게 연결한다.
React 화면에도 같은 경로·언어의 핵심 내용과 FAQ가 접근 가능해야 한다.
정적 HTML에만 긴 본문을 넣고 JavaScript 실행 후 없어지는 별도 SEO 원고를 만들지 않는다.
집중 편집 진입 후 안내를 접는 정상 UX는 유지하되 사용법으로 돌아갈 수 있게 한다.

기존 blocks가 title/paragraphs/items만 지원한다면,
입력→출력 표나 코드 예시를 평문 문자열로 우겨 넣기 전에
현재 렌더러로 표현 가능한지 확인한다.
필요한 최소한의 typed example 표현만 추가하고 React와 정적 renderer에 함께 연결한다.
새 마크다운 프레임워크나 임의 HTML 실행을 도입하지 않는다.
중괄호·꺾쇠·따옴표·표·코드의 escaping과 접근성을 확인한다.

사이트 메타데이터 제목을 split해 H1을 추측하는 경로도 확인한다.
사용자에게 보여줄 H1과 브랜드가 붙는 검색 제목을 안정적으로 구분한다.
head의 title/description/canonical/JSON-LD가 중복 누적되지 않게 한다.

==================================================
7. URL·canonical은 원고 보강과 구분해 처리한다
==================================================

기존 URL은 유지한다. 동의어별 새 페이지와 리디렉션을 만들지 않는다.
현재 canonical/robots/sitemap/hreflang 정책을 먼저 대조한다.
부록 B의 currentCanonicalFromCode는 당시 판독값이지 현재 상태를 강제하는 명령이 아니다.

PDF의 page-numbers/header-footer/watermark/stamp가 finish에 통합돼 있다면:
- 각 경로의 고유한 설명과 실제 초기 작업은 개선한다.
- canonical이 통합된 상태를 독립 유입 완료로 보고하지 않는다.
- 이번에는 승인 없이 네 경로를 일괄 self-canonical로 전환하지 않는다.
- 별도의 고유 콘텐츠·독립 운영이 충분한지 근거와 변경안을 기록한다.
- 미결정 항목 때문에 나머지 원고 반영을 중단하지 않는다.
이미 후속 변경으로 정책이 확정돼 있다면 이유 없이 옛 통합 상태로 되돌리지 않는다.

canonical과 표시할 문구의 선택은 구분한다.
대표 URL이 finish라고 세부 기능의 안내를 전부 finish 일반 문장으로 덮지 않는다.

오피스 기본 경로가 자동으로 /app/로 이동하는 경우에는
검색 안내 경로·?guide=1·실제 실행 화면의 역할이 현재 어떻게 나뉘는지 확인한다.
검색 원고를 넣으려고 자동 시작이나 격리 이동을 임의로 폐지하지 않는다.
실행 후 사라지는 정적 원고만 추가해 사용자와 검색에 모두 반영됐다고 보고하지 않는다.
안내 경로 운영을 바꿔야 한다면 해당 변경안만 별도로 제시하고 기존 기능은 유지한다.

/app/, xls-preserve, 문서 비교 세션 결과 화면은 독립 유입 콘텐츠 목표에서 제외한다.
공개 사용법은 일반 안내에 두고, 작업 화면의 noindex·광고 제외·사이트맵 처리는 실제 정책과 대조한다.
검색 목표에서 제외한다는 이유로 robots/광고 정책을 이번에 무작정 일괄 변경하지 않는다.

공통 안내와 관련 도구 링크는 실제 존재하는 올바른 언어 경로로 연결한다.
예: 엑셀 병합 → 엑셀 비교·정리, PDF 스캔 텍스트 → OCR,
사진 위치정보 → 메타데이터 제거, 보이는 글자 가리기 → 개인정보 가리기.
새 탭/전체 이동이 보안상 필요한 도구는 기존 내비게이션 정책을 보존한다.

==================================================
8. 한국어·영어와 데이터 안전성
==================================================

한국어와 영어를 함께 반영하되 한국어 검색어를 영어 원고에 복사하지 않는다.
영문 표현은 부록 B의 seed를 참고하고 확인되지 않은 검색량으로 순위를 매기지 않는다.
새로운 외부 자료로 표현·정책·계산 기준을 보충했다면 출처와 추가 판단을 기록한다.

HWP의 언어 지원 예외를 유지한다.
한국 급여·휴일·연차를 전 세계 공통 기능인 것처럼 번역하지 않는다.
미지원 언어를 영어 fallback으로 조용히 채워 번역 완료라고 하지 않는다.

DOCX 예제의 {이름}은 중괄호 한 쌍을 유지한다.
앱 번역 치환에 원래 사용되는 {{변수}}까지 일괄 바꾸지 않는다.
예제 태그와 i18n interpolation을 구분해 실제 표시·정적 출력·템플릿 결과를 확인한다.

가이드 오류를 catch 후 []로 숨기지 않는다.
개발·CI·정적 생성에서는 언어/경로/guideKey/필드를 표시하고 실패한다.
의도적인 빈 항목과 누락된 필수 원고를 구분한다.
운영에서는 가이드 전용 경계에서 처리하고 정상 편집 영역의 세션을 깨뜨리지 않는다.
필수 안전 안내 누락을 숨긴 채 작업을 계속 허용하지 않는다.

이 작업을 위해 추적 이벤트·외부 SEO API·광고 배치를 새로 추가하지 않는다.
원고에 ‘서버 전송 없음’이라고 쓰려면 작업 파일과 일반 네트워크 요청을 구분한다.
복구 초안·임시 전달·프로그램 캐시 예외를 삭제하거나 전부 즉시 소멸한다고 단정하지 않는다.

==================================================
9. 회귀 검증은 문구 연결과 실제 화면까지 확인한다
==================================================

A. 조사 범위
현재 실제 경로 목록과 부록 A/B의 합집합을 만들고,
지원 언어별로 반영/유지/제외/결정 대기/미검증을 모두 표시한다.
44개만 숫자 채우기로 검사하지 않는다. 새로 추가된 도구가 있으면 근거와 함께 포함한다.
한국어 전용 경로를 제외한 영어 대응도 확인한다.

B. 데이터·메타데이터
- 모든 필수 guideKey와 block/FAQ ID가 존재한다.
- 비어 있는 제목·깨진 배열·삭제된 키·중복 ID가 없다.
- 예제 표·코드·번역 치환이 정상 표시된다.
- 공개 title/H1/description이 실제 작업과 맞는다.
- 기존 내용 중 보존해야 할 제한·안전 안내가 사라지지 않았다.
- FAQPage를 사용하는 경로에서는 표시되는 실제 FAQ와 구조화 데이터가 맞는다.
- 검색어 나열·내부 편집 지시·가짜 성과·가짜 다운로드 링크가 없다.

C. 초기 HTML과 브라우저
JavaScript를 실행하지 않은 초기 HTML에서 핵심 소개·상세 공개 안내·해당 FAQ를 확인한다.
이어서 JavaScript 실행 후 같은 URL/언어에서 해당 내용을 읽을 수 있는지 확인한다.
DOM 형식이 완전히 같아야 한다는 뜻은 아니며 내용·범위·의미가 일치해야 한다.
JSON-LD에만 있는 문장이나 실행 후 숨겨지는 별도 SEO 본문은 실패로 처리한다.
앵커·관련 도구 링크·언어 전환·새로고침도 확인한다.

D. 사용자 작업
모든 변경된 공개 경로를 browser smoke test로 순회한다.
제목만 보이는 것 말고 파일 선택·도구 UI·공개 안내가 실제로 표시되는지 확인한다.
대표 도구의 기존 기능 테스트와 새로 게시할 예제 결과를 확인한다.
가이드 hook·원고 변경으로 PDF/오피스/HWP가 재마운트되거나 오류 경계로 빠지면 실패다.
일반 페이지와 집중 편집 화면을 구분해 긴 원고가 작업 공간을 침범하지 않는지 확인한다.
네 테마·모바일에서 표/예제/FAQ가 넘치거나 버튼을 가리지 않는지 본다.

E. 기존 검사와 CI
기존 검사에서 옛 파일의 정확한 문자열만 찾는 부분은 새 정본/필수 내용 계약과 함께 이관한다.
검사를 통과시키려고 숨은 키에 문장을 복사하거나 throw를 삭제하지 않는다.
의미 보존·필수 지원 범위 검증을 단순 출력 스냅샷 비교로 대체하지 않는다.
필수 FAQ/guideKey를 하나 제거했을 때 검사가 실제로 실패하는지도 확인한다.

현재 package.json의 실제 명령을 확인하고 실행한다.
가이드/i18n/관련 unit 검사 → 최신 build → test:static → 해당 browser/기능 검사 순서로 검증한다.
명령이 없는 경우 없는 사실을 적고 기존 테스트 체계로 연결한다.
문서에 테스트 이름만 적고 실제 스크립트/CI 호출이 없는 상태로 완료하지 않는다.
오류는 가능한 범위에서 모아 한 번에 보고하고 exit code로 실패를 전달한다.

==================================================
10. 진행 순서·최종 보고·완료 기준
==================================================

진행:
1) 이전 원고의 실제 반영 상태와 최신 동작 대조.
2) 기존 원고+검색 의도의 페이지별 통합표 작성.
3) 우선순위 높은 도구부터 title/소개/소제목/예시/FAQ/내부 링크 보강.
4) 나머지 도구·기존 세부 경로·홈/전체 도구/서비스 페이지 반영.
5) 정본·정적 출력·언어·검증 연결 보강.
6) 전체 대상 순회 및 최종 결과 보고.

P1부터 시작하되 P2/P3를 누락한 채 전수 완료라고 하지 않는다.
추가 승인이 필요한 canonical/안내 경로 변경은 해당 항목만 분리한다.
기존 계획 승인을 반복 요청하면서 확정된 콘텐츠 작업을 중단하지 않는다.

최종 보고에는 다음을 남긴다.
- 실제 브랜치·HEAD와 수정 범위.

## 2. AdSense와 사용자 경험에 대한 기준

Google의 공식 준비 안내는 독창적이고 유용한 콘텐츠, 읽기 쉬운 구성, 탐색 가능한 사이트와 완성된 페이지를 강조한다. 이 문서는 특정 글자 수·FAQ 수·페이지 수를 승인 조건으로 삼지 않으며, 아래 원고의 적용도 승인을 보장하지 않는다.

Publisher Policies는 콘텐츠가 없거나 가치가 낮은 화면, 공사 중인 화면, 알림·탐색 등 행동용 화면에 광고를 게재하는 것을 제한한다. 따라서 오류·로딩·전용 편집 화면에 장문을 넣어 광고 대상처럼 꾸미지 않는다. 저장/다운로드/드롭 영역은 광고와 혼동되지 않게 분리한다. 실제 Auto ads와 동적 화면 상태의 광고 정책은 별도 검증한다.

Google Search의 사람 중심 콘텐츠 가이드는 검색을 위한 분량 채우기보다 독자가 목적을 달성하는 콘텐츠를 권장한다. 이는 검색 품질 안내이며 AdSense의 독립적인 승인 기준으로 혼동하지 않는다.

## 3. 배치 원칙

- **도구 상단:** 무슨 결과를 만드는지와 필수 준비물 2~3문장.
- **설정 옆:** 선택 기준과 예상과 다른 결과를 막는 짧은 설명.
- **작업 영역 아래:** 합성 입력·출력 예제, 결과 검토, 도구 고유 FAQ.
- **집중 편집·로딩·오류 화면:** 현재 상태·다음 행동·복구 방법만. 자세한 안내는 별도 접근 경로를 유지.

모든 페이지를 동일한 긴 양식으로 채우지 않는다. 간단한 도구는 짧은 전후 예제가 장황한 설명보다 낫다. 세부 경로는 공통 지원 안내를 재사용하되 해당 작업의 목적과 예시를 덧붙인다. 같은 설명을 제목만 바꾸어 여러 주소로 복제하지 않는다.

## 4. 도구별 추가 원고

아래 ‘게시용 추가 원고’는 신규 제안이다. 현재 코드에서 제공하지 않는 기능을 새로 지원한다고 선언하는 것이 아니다. 수치·옵션명·샘플 출력은 반영 직전 실제 화면과 테스트 파일로 대조한다. 기존에 이미 같은 내용이 있다면 추가로 쌓지 않고 합친다.


### 01. 엑셀 병합

경로: `/tools/excel-merger`  
가이드 연결: `excel`  
우선순위: 높음

**보강 방향:** 기존 수식·서식 보존 FAQ는 유지하고, 병합 방식 선택 바로 아래에 실제 결과 예를 추가한다.

#### 게시용 추가 원고

##### 합친 뒤 어떤 모습이 필요한가요?

부서별 자료를 한 파일에 모으되 각 표를 따로 보고 싶다면 **시트별 병합**을 선택하세요. 매달 같은 항목으로 작성한 목록을 길게 모으려면 **세로 병합**, 같은 순서로 나뉜 표를 옆으로 붙이려면 **가로 병합**을 사용합니다.

가로 병합은 고객번호나 사번을 찾아 같은 사람끼리 연결하는 기능이 아닙니다. 두 표의 행 순서가 다르면 잘못된 값이 나란히 놓일 수 있으므로, 먼저 자료의 순서를 확인하세요. 결과를 저장한 뒤에는 시트 수와 첫 행·마지막 행, 중요한 수식 몇 개를 확인하세요.

#### 예제·선택 도움

예시: 1월·2월 자료를 각 탭으로 남기면 시트별, 같은 열의 거래내역을 아래로 이어 붙이면 세로. 가로 병합은 두 자료의 행 순서가 같다는 전제에서 사용한다. 제목 행을 자동으로 한 번만 남긴다고 안내하지 않는다.

#### FAQ 추가·교체안


**병합과 비교 중 무엇을 써야 하나요?**  
여러 자료를 한 파일로 모으려면 병합, 두 자료에서 무엇이 달라졌는지 찾으려면 엑셀 비교를 선택하세요.


**합친 결과에서 무엇을 확인하면 좋나요?**  
파일과 시트의 순서, 반복된 열 이름 행, 빠진 행, 수식의 참조와 표시값을 먼저 확인하세요. 원본은 결과 확인이 끝날 때까지 따로 보관하세요.


**반영 전 확인:** 중복 머리글·빈 영역·매크로·보존 옵션에 관한 기존 지원 제한을 삭제하지 않는다.


### 02. 엑셀 비교

경로: `/tools/excel-compare`  
가이드 연결: `excelCompare`  
우선순위: 높음

**보강 방향:** 이미 있는 모드 설명을 반복하지 말고, 작은 전후 표와 결과를 읽는 순서를 추가한다.

#### 게시용 추가 원고

##### “달라짐”과 “서로 연결하지 못함”은 다릅니다

수정 전후의 비슷한 표는 행과 열을 맞춰 비교하고, 순서가 다른 명단은 사번·상품코드처럼 같은 대상을 찾을 수 있는 기준 항목으로 비교하세요. 금액·날짜·거래처가 서로 맞는 거래를 확인하려면 거래 내역 맞추기를 사용합니다.

결과의 **변경**은 연결된 항목의 값이 다른 경우입니다. **중복**이나 **연결이 모호한 항목**은 잘못된 자료라고 확정한 것이 아니라, 같은 대상을 하나로 정하기 어려운 경우입니다. 이런 항목은 원본과 보조 기준을 함께 확인하세요.

#### 예제·선택 도움

예시 자료: 왼쪽은 `P-01 10개 / P-02 20개`, 오른쪽은 `P-02 25개 / P-01 10개`입니다. 상품코드를 기준으로 연결하면 순서가 달라도 P-01은 수량이 같고 P-02는 달라졌다는 의미를 읽을 수 있습니다. 실제 fixture를 만들어 보고서와 일치하는지 확인한 뒤 화면 예시로 게시합니다.

#### FAQ 추가·교체안


**기준 항목에 이름을 사용해도 되나요?**  
같은 이름이 여러 번 나올 수 있다면 사번·주문번호처럼 항목을 구분할 수 있는 값을 우선 확인하세요. 이름만으로 연결한 결과는 중복 목록도 함께 살펴보세요.


**변경 항목이 예상보다 너무 많으면 어떻게 하나요?**  
비교할 시트와 열 이름 행이 맞는지, 날짜·숫자의 표시 방식이나 공백이 다른지 먼저 확인하세요. 허용 오차를 크게 바꾸기 전에 원본 몇 행을 직접 대조하세요.


**반영 전 확인:** 위치 모드를 단순 A1 대 A1 비교로 축소 설명하지 않는다. 중복 목록의 같은 줄끼리 확정 연결됐다고 쓰지 않는다.


### 03. 엑셀 정리

경로: `/tools/excel-cleaner`

#### 게시용 추가 원고

##### 줄을 지우기 전에 “중복”의 기준을 정하세요

이름이 같다고 같은 사람은 아니고, 상품명이 같아도 주문번호가 다르면 다른 거래일 수 있습니다. 중복 정리나 행 삭제를 적용하기 전에 어떤 열을 기준으로 같은 자료를 판단할지 정하세요.

처음에는 공백 정리처럼 변화가 작은 규칙 하나만 적용해 보세요. 규칙은 위에서 아래로 실행되므로, 공백을 정리한 뒤 중복을 제거한 결과와 반대 순서의 결과는 달라질 수 있습니다. 결과 파일뿐 아니라 처리 보고서의 변경·제외 항목도 확인하세요.

#### 예제·선택 도움

예시: `서울`, ` 서울 `을 공백 정리하면 같은 값이 될 수 있습니다. 하지만 `0012`와 `12`는 상품코드라면 다른 값일 수 있으므로 숫자 변환을 먼저 적용하지 않습니다.

#### FAQ 추가·교체안


**코드 앞의 0을 유지하고 싶어요.**  
사번·상품코드·전화번호는 계산할 숫자와 구분하세요. 숫자 변환을 적용하기 전에 해당 열을 확인하고, 결과에 앞자리 0이 남아 있는지 샘플로 확인하세요.


**정리한 파일의 행 수가 줄었어요.**  
빈 행 삭제·중복 제거·필터 등 선택한 규칙을 확인하세요. 원본과 결과의 행 수만 비교하지 말고 처리 보고서에서 제외된 이유도 함께 살펴보세요.


**반영 전 확인:** 현재 A1 수식 갱신 지원과 CSV 안전 모드 제한을 보존한다. 모든 수식이 깨진다거나 모두 보존된다고 쓰지 않는다.

##### 같은 표를 다른 프로그램이 읽을 수 있게 바꿉니다

엑셀에서 저장한 CSV를 프로그램에 넘길 JSON으로 바꾸거나, 웹페이지에 넣을 HTML 표로 만들 때 사용하세요. 이 도구는 표의 내용을 다시 작성하는 것이 아니라 같은 데이터를 다른 표시 형식으로 바꾸는 도구입니다.

첫 행의 열 이름이 이름·수량처럼 분명한지 확인하세요. 쉼표나 줄바꿈이 들어 있는 셀도 있을 수 있으므로 CSV를 메모장에서 단순히 쉼표로 나누어 고치기보다 변환 결과의 행·열 수와 셀 내용을 확인하는 편이 좋습니다.

#### 예제·선택 도움

CSV 예시:
```csv
상품,수량
노트,3
펜,5
```
JSON 예시:
```json
[{"상품":"노트","수량":"3"},{"상품":"펜","수량":"5"}]
```
이 예시는 문자열 값을 사용하는 개념 예시입니다. 실제 숫자 타입 추론 여부는 현재 변환기로 실행해 확정한 뒤 게시합니다.

#### FAQ 추가·교체안


**엑셀의 색상과 수식도 함께 옮겨지나요?**  
CSV·JSON·HTML 표 사이의 데이터 변환입니다. 엑셀 통합문서의 셀 서식·수식·차트를 그대로 옮기는 도구로 사용하지 마세요.


**한글이 깨지면 무엇을 확인하나요?**  
CSV를 읽는 문자 인코딩 설정과 원본 파일이 저장된 방식을 확인하세요. 변환 전 미리보기에서 한글과 구분자가 제대로 읽히는지 먼저 살펴보세요.


**반영 전 확인:** JSON 숫자/문자열 타입과 빈 셀 처리 결과는 fixture로 확인. XLSX 직접 입력 기능으로 소개하지 않는다.


### 05. PDF 도구

경로: `/tools/pdf-editor`  
가이드 연결: `pdfEditor.standard / pdfEditor.convert`  
우선순위: 높음

**보강 방향:** 공통 안내 앞에 작업 선택 안내를 추가하고, 세부 페이지에는 해당 작업의 고유 예시를 표시한다.

#### 게시용 추가 원고

##### PDF를 그대로 정리할지, 다른 파일로 바꿀지 먼저 고르세요

제출할 파일을 하나로 모으거나 필요한 페이지만 남기려면 **페이지 편집**을 사용하세요. 글자 내용을 다시 작성하는 기능이 아니라 페이지의 순서·구성과 방향을 정리하는 작업입니다.

페이지를 사진처럼 쓰려면 **PDF→이미지**, 여러 사진을 한 문서로 묶으려면 **이미지→PDF**를 고르세요. PDF의 글자를 편집 가능한 문서로 가져오려면 **문서 변환**, 스캔한 문서에 검색 가능한 글자를 더하려면 **OCR**을 사용합니다. 변환 후에는 원문과 결과를 함께 확인하세요.

#### 예제·선택 도움

작업 선택 카드: “제출 서류 3개를 하나로”→병합, “계약서 2~4쪽만”→분할/추출, “페이지를 PNG로”→이미지, “스캔본에서 단어 검색”→OCR. 실제 문서가 아닌 합성 예시를 사용한다.

#### FAQ 추가·교체안


**페이지 편집에서 PDF 본문 글자를 직접 고칠 수 있나요?**  
이 화면은 페이지 순서·삭제·회전·추출과 마무리 표시를 다룹니다. 본문을 다시 작성하려면 변환 결과나 원래 문서 파일을 별도 편집기에서 수정해야 합니다.


**이미지 변환과 OCR은 같은 기능인가요?**  
이미지 변환은 페이지의 보이는 모습을 PNG·JPG로 저장하고, OCR은 이미지 속 글자 모양을 읽어 텍스트로 다루는 작업입니다. 글자가 사라진 변환 결과를 OCR으로 대신 복구하는 방식으로 안내하지 않습니다.


**반영 전 확인:** 암호·서명·양식·링크의 기존 제한 유지. 실제 원본의 누락은 정상 결과가 아니므로 다운로드 완료와 내용 확인을 구분한다.


### 06. 워드 일괄 생성

경로: `/tools/document-generator`  
가이드 연결: `documentGenerator`  
우선순위: 최우선

**보강 방향:** 현재 사용 순서는 열 연결에서 시작한다. 그 앞의 준비 단계와 입력→출력 예시를 복원한다.

#### 게시용 추가 원고

##### 양식 하나와 목록 하나로 안내문 여러 개를 만듭니다

매번 같은 안내문을 복사해 이름과 부서를 바꾸고 있다면, 워드 양식에 바뀔 자리를 표시하고 엑셀 목록을 연결해 보세요. 이 도구는 글을 새로 쓰거나 이메일을 보내지 않고, 준비한 양식에 목록의 값을 채워 DOCX 파일을 만듭니다.

워드 양식에서 이름이 들어갈 자리에 `{이름}`, 부서가 들어갈 자리에 `{부서}`처럼 **중괄호 한 쌍**을 적습니다. 엑셀 첫 행에는 `이름`, `부서`처럼 열 이름을 쓰고 다음 행부터 데이터를 입력하세요. 파일을 선택한 뒤 각 열을 양식 항목에 연결하고, 문서 한 개를 먼저 만들어 배치와 숫자·날짜를 확인하세요.

#### 예제·선택 도움

워드 양식:
```text
{이름} 님, 안녕하세요.
소속 부서: {부서}
교육 일정을 확인해 주세요.
```
엑셀 목록:

| 이름 | 부서 |
|---|---|
| 김민수 | 영업팀 |
| 이서연 | 운영팀 |

파일명 규칙을 `{이름}_안내문.docx`로 **지정한 경우** 각각 `김민수_안내문.docx`, `이서연_안내문.docx`가 목표 결과입니다. 기본 파일명이 자동으로 이렇게 정해진다고 쓰지 않습니다. 예제 파일은 실제 생성 엔진으로 확인한 후 다운로드 자료로 제공합니다.

#### FAQ 추가·교체안


**엑셀 열 이름이 고객명이고 양식에는 {이름}이라고 적었어요.**  
고객명 열을 양식의 이름 항목에 연결하세요. 연결 이름 입력란에는 중괄호 없이 이름을 지정합니다. 양식과 열을 정확히 연결한 뒤 샘플을 확인하세요.


**미리보기 표가 맞으면 전체 문서도 바로 보내도 되나요?**  
미리보기 표는 넣을 값을 확인하는 단계입니다. 샘플 DOCX를 실제 문서 프로그램에서 열어 줄바꿈·표·날짜·금액과 파일명을 확인한 뒤 전체 생성하세요.


**값이 빈 것과 항목 연결이 없는 것은 같은가요?**  
아닙니다. 연결한 열의 빈 값은 빈 내용이 될 수 있지만, 필요한 열을 연결하지 않은 상태는 연결을 고쳐야 합니다. 필수 값이 빠지지 않았는지 샘플을 확인하세요.


**반영 전 확인:** {{이름}} 금지. 반복/조건/이미지 태그 미지원 유지. 예제 이름은 가상값이며 실제 업무 문서 재사용 금지.


### 07. 문서 비교

경로: `/tools/document-compare`  
가이드 연결: `documentCompare`  
우선순위: 높음

**보강 방향:** 제목 “ 사용 안내”를 먼저 고치고, 결과 형식 선택·결과 해석 순서를 추가한다.

#### 게시용 추가 원고

##### 수정 전 문서를 왼쪽에, 수정 후 문서를 오른쪽에 넣으세요

보고서나 안내문을 여러 번 수정하다 보면 어디가 바뀌었는지 놓치기 쉽습니다. 문서 비교는 두 버전의 글·표·서식 차이를 표시해 검토할 위치를 찾도록 돕습니다. Word 문서는 Word 문서끼리, 한글 문서는 한글 문서끼리 연결하세요.

바뀐 부분을 바로 읽으려면 웹 비교를, 검토 목록을 정리하려면 엑셀 보고서를 선택하세요. 두 파일이 모두 DOCX이면 Word에서 확인할 변경 내용 추적 결과도 만들 수 있습니다. 변경 표시가 문서의 업무상 의미까지 판정하는 것은 아니므로 원문과 함께 읽어 주세요.

#### 예제·선택 도움

예시: 같은 안내문의 제출일을 “10월 1일”에서 “10월 5일”로 바꾸고 표의 담당 부서 한 칸만 수정한 합성 DOCX 두 개. 본문 변경과 표 변경을 각각 어디서 확인하는지 보여준다.

#### FAQ 추가·교체안


**같은 글인데 변경으로 표시될 수 있나요?**  
서식이나 문서 내부 구조가 달라질 수 있습니다. 표시된 구간을 원문과 함께 읽고, 서식 변경을 포함한 비교인지 확인하세요.


**전체 차이를 다 읽어야 하나요?**  
먼저 추가·삭제·변경 목록을 보고, 날짜·금액·대상자처럼 중요한 내용을 우선 확인해 보세요. 표 비교와 기타 문서 영역을 선택했는지도 확인하세요.


**반영 전 확인:** Word-HWP 교차 비교를 지원한다고 쓰지 않는다. 결과 다운로드가 법적/업무적 동일성을 보증한다고 쓰지 않는다.


### 08. PDF 비교

경로: `/tools/pdf-compare`  
가이드 연결: `pdfCompare`  
우선순위: 최우선

**보강 방향:** 현재 blocks의 한 문장 안내를 실제 사용 사례와 화면/텍스트 비교 해설로 확장한다.

#### 게시용 추가 원고

##### 글자 비교와 화면 비교를 함께 확인하세요

PDF는 글자 정보와 페이지의 보이는 모습이 서로 다를 수 있습니다. **텍스트 비교**는 PDF에서 읽어 낸 글자 차이를 확인하고, **화면 비교**는 페이지를 그린 모습의 차이를 확인합니다. 사진처럼 스캔된 문서는 읽어 낼 글자가 없을 수 있으므로 텍스트 결과만으로 내용이 같다고 판단하지 마세요.

먼저 같은 내용을 담은 페이지끼리 연결됐는지 확인하세요. 수정본 앞에 표지가 추가되었다면 이후 쪽이 한 장씩 밀릴 수 있습니다. 페이지를 맞춘 뒤 다시 비교하고, 숫자·날짜·서명·표가 바뀐 위치를 원문과 함께 살펴보세요.

#### 예제·선택 도움

예시: 원본은 표지 없이 3쪽, 수정본은 새 표지+본문 3쪽. 원본 1쪽과 수정본 2쪽을 대응해야 같은 내용을 비교한다는 도식. 현재 가이드가 수동 대응을 지원한다고 명시하므로 실제 UI에서 연결 방식 확인 후 게시.

#### FAQ 추가·교체안


**스캔 PDF에서 텍스트 결과가 비면 내용이 없는 건가요?**  
아닙니다. 글자 모양이 이미지에 들어 있으면 PDF에서 추출할 텍스트가 없을 수 있습니다. 화면 비교를 확인하고, 검색용 텍스트가 필요하면 PDF OCR 기능을 별도로 사용하세요.


**페이지가 모두 달라 보이면 무엇부터 확인하나요?**  
표지 추가·페이지 삭제·순서 변경 때문에 비교 쪽이 밀렸는지 먼저 확인하세요. 페이지 연결을 맞춘 뒤에도 차이가 나면 크기·방향과 실제 본문을 확인하세요.


**반영 전 확인:** “모든 차이 검출”, “동일성 판정”, 자동 OCR 지원을 약속하지 않는다. 구체 임계값은 코드와 맞춘다.


### 09. 한글 문서 편집

경로: `/tools/hwp-editor`  
가이드 연결: `hwpEditor / 현재 연결 재확인`  
우선순위: 중간

**보강 방향:** 편집 전 준비와 저장 후 검토 기준을 추가한다. 집중 편집 화면에 장문을 삽입하지 않는다.

#### 게시용 추가 원고

##### 원본을 보관하고, 저장한 파일을 다시 확인하세요

한글 문서를 급히 열어 문장이나 표를 수정할 때 사용할 수 있습니다. 브라우저 편집기의 지원 범위 안에서 글·표·서식을 편집하고 새 파일을 저장하세요.

원래 문서에 쓰인 글꼴이나 복잡한 개체가 다르게 표시될 수 있습니다. 제출용 문서는 저장한 파일을 실제 사용할 프로그램에서 다시 열어 페이지 수, 줄바꿈, 표의 잘림과 이미지 위치를 확인하세요. 중요한 원본은 덮어쓰지 않고 따로 보관하는 편이 좋습니다.

#### 예제·선택 도움

#### FAQ 추가·교체안


**오피스 편집기와 무엇이 다른가요?**  
이 도구는 HWP·HWPX 등 한글 문서에 맞춰 제공됩니다. DOCX·XLSX·PPTX를 편집하려면 오피스 편집기를 선택하세요.


**화면에서 잘 보이면 바로 제출해도 되나요?**  
저장된 파일을 다시 열어 확인하세요. 브라우저에서 보던 모습과 최종 사용하는 프로그램의 줄바꿈·페이지 배치가 다를 수 있습니다.


**반영 전 확인:** 현재 rhwp 버전, HML 저장 제한, 복구 초안 정책과 맞춰야 한다. 영어 미지원 경로에 가짜 영어 도구를 만들지 않는다.

#### 게시용 추가 원고

##### 준비가 끝나기 전에도 파일을 골라 둘 수 있습니다

페이지를 열면 브라우저에서 오피스 편집 환경을 준비합니다. 처음에는 프로그램과 글꼴을 내려받아 시간이 걸릴 수 있고, 다음 실행부터는 저장된 프로그램 파일을 재사용할 수 있습니다. 진행 안내를 확인하면서 편집할 파일을 선택하거나 드롭 영역에 놓으세요.

준비가 끝나면 선택한 문서를 엽니다. 문서 편집 중에는 사이트 검색창 대신 편집기 메뉴와 저장 도구를 사용합니다. 작업을 마치면 **저장 및 다운로드**로 결과 파일을 받아 주세요. 다운로드한 파일을 다시 열어 글꼴·페이지 나눔·수식 결과를 확인한 뒤 공유하세요.

#### 예제·선택 도움

짧은 상태 안내: “편집 환경 준비 중 — 파일을 미리 골라 둘 수 있습니다.” / “준비 완료 — 편집할 파일을 놓으세요.” / “문서를 여는 중” / “저장한 파일을 내려받았습니다.” 표시를 실제 상태에 연결한다.

#### FAQ 추가·교체안


**다음에도 프로그램 파일을 다시 받아야 하나요?**  
브라우저에 필요한 프로그램 파일이 남아 있으면 재사용할 수 있습니다. 사이트 데이터를 지우거나 다른 기기·브라우저를 사용하면 다시 준비할 수 있습니다.


**Word·Excel·PowerPoint와 완전히 같은 결과가 나오나요?**  
LibreOffice 기반 편집 환경이므로 글꼴·줄바꿈·고급 기능 등에서 차이가 있을 수 있습니다. 중요한 결과는 원래 사용하던 프로그램에서도 확인하세요.


**저장이 끝났는지 어떻게 확인하나요?**  
완료 안내와 함께 브라우저가 실제로 결과 파일을 내려받았는지 확인하세요. 화면에 문서가 보이는 것만으로 파일 저장이 끝난 것은 아닙니다.


**반영 전 확인:** officeAssets의 합계 264,362,080 bytes는 자산 크기 기준 약252.1MiB. 네트워크 압축 전송량과 구분하고 텍스트에 고정 숫자 복제하지 않는다. 실제 준비 중 선택 기능 정상화 후 해당 문구 게시.

**모자이크만 하면 개인정보가 모두 안전한가요?**  
효과의 강도와 가린 범위를 직접 확인해야 합니다. 문서의 글자를 분명하게 가릴 목적이라면 개인정보 가리기 도구와 결과 확인 절차를 검토하세요.


**반영 전 확인:** 생성형 확대/자동 누끼/객체 인식 같은 미지원 기능을 추가 설명하지 않는다.

#### 게시용 추가 원고

##### 빠르게 저장할지, 시작 지점을 정확히 맞출지 고르세요

원본 그대로 복사하는 방식은 영상을 다시 압축하지 않아 빠르지만, 자르기 시작점이 가까운 재생 기준 장면에 맞춰질 수 있습니다. 지정한 순간에 더 정확히 시작하거나 크기·회전·호환 형식을 바꾸려면 다시 변환하는 방식을 검토하세요.

여러 영상을 합칠 때는 순서뿐 아니라 가로·세로 비율, 해상도와 소리 구성이 같은지도 확인해야 합니다. 결과를 저장한 뒤 처음·연결 지점·끝부분을 재생해 화면과 소리가 의도대로 이어지는지 확인하세요.

#### 예제·선택 도움

예시: 회의 녹화에서 00:30~01:10을 남기는 경우. 빠른 복사와 다시 변환의 의미를 설명하되, 모든 파일에서 정확히 같은 성능·품질 수치를 약속하지 않는다.

#### FAQ 추가·교체안


**MP4인데도 다른 기기에서 재생되지 않을 수 있나요?**  
MP4는 파일을 담는 형식이고 내부 영상·음성 압축 방식은 다를 수 있습니다. 사용할 기기에서 결과를 재생해 보고, 화면에서 제공하는 호환 설정을 확인하세요.


**남은 시간이 갑자기 바뀌는 이유는 무엇인가요?**  
다음 영상이나 최종 연결 단계로 넘어가면 처리 속도가 달라질 수 있습니다. 표시된 예상 시간뿐 아니라 현재 처리 단계와 진행 로그를 함께 확인하세요.


**반영 전 확인:** 기존 영상 화면 광고 제외/격리 정책 유지. 처리속도 수치나 모든 코덱 호환을 약속하지 않는다.


### 13. 오디오 편집

#### 게시용 추가 원고

##### 구간을 없앨지, 길이를 유지한 채 소리만 끌지 고르세요

파형에서 필요한 부분을 드래그해 선택하고 먼저 재생해 보세요. **삭제·잘라내기**는 선택한 구간을 빼고 뒤의 소리를 앞으로 당깁니다. **음소거**는 구간의 길이는 남겨 두고 그 부분의 소리만 없앱니다.

#### 예제·선택 도움

예시: 20초 녹음에서 중간 3초를 삭제하면 전체 길이가 줄어들고, 같은 부분을 음소거하면 전체 길이는 유지됩니다. 실제 구현의 선택 구간 처리로 확인 후 게시.

#### FAQ 추가·교체안


**파형이 작게 보이면 소리가 작은 건가요?**  
파형은 위치와 구간을 찾는 데 도움이 되지만 듣는 환경까지 알려주지는 않습니다. 선택 구간을 직접 재생해 판단하세요.


**편집 내용이 사라지지 않게 하려면 어떻게 하나요?**  
필요한 결과를 WAV나 MP3로 저장하세요. 새 파일을 열면 기존 편집 기록과 클립보드가 정리되므로, 다른 파일로 바꾸기 전에 결과를 확인하세요.


**반영 전 확인:** 선택 영역/재생 커서라는 이름 사용. 피치 변경을 성별·신원 변환 기능처럼 표현하지 않는다.

#### FAQ 추가·교체안


**파일 사이에 빈 줄이 너무 많이 생겨요.**

**문장을 자연스럽게 이어 써 주나요?**  
아닙니다. 입력한 글을 정해진 순서와 구분자로 연결합니다. 문장의 표현이나 내용은 결과를 보면서 직접 확인하세요.


**반영 전 확인:** 원본 TXT 변경 없음과 로컬 처리 안내는 한 번만 유지한다.


### 15. 텍스트 정리

#### 게시용 추가 원고

##### 줄바꿈을 없애기 전에 글의 구조를 확인하세요

중복 줄 제거도 같은 상품명이 서로 다른 거래를 뜻하는 경우에는 주의가 필요합니다. 필요한 작업 하나를 적용한 뒤 원문과 결과를 비교하고, 목록 수와 띄어쓰기가 의도대로인지 확인하세요.

#### 예제·선택 도움

예시: 문장 “보고서를
확인해 주세요.”는 줄바꿈 합치기 대상이 될 수 있지만 “서울
부산
대구”는 항목 경계를 유지해야 하는 목록이다. 실제 결합 시 공백 처리 결과와 예문을 맞춘다.

#### FAQ 추가·교체안


**같은 뜻의 문장도 중복으로 찾아 주나요?**  
문장의 의미를 비교하는 도구가 아닙니다. 정해진 텍스트 규칙을 적용하므로, 표현이 다른 문장이 같은 뜻인지 직접 판단해야 합니다.


**영문 표기 변경은 무엇에 쓰나요?**  
여러 단어를 camelCase·snake_case 같은 규칙으로 맞출 때 사용합니다. 사람 이름·문서 제목에 적용하기 전 원하는 표기인지 결과를 확인하세요.


**반영 전 확인:** 한국어 검사 결과는 문맥 교정 보증이 아니라 규칙 기반 참고임을 유지한다.


### 16. 코드 포맷터

가이드 연결: `formatter`

**보강 방향:** 들여쓰기 전후 예와 문법 확인/실행의 차이를 추가한다.

#### 게시용 추가 원고

##### 읽기 좋게 정리하는 것과 실행해 보는 것은 다릅니다

길게 붙은 JSON·SQL·XML을 줄과 들여쓰기로 나누어 읽기 쉽게 만듭니다. 오류가 표시되면 해당 위치의 따옴표·괄호·구분자를 확인하세요. 잘못된 값을 임의로 바꿔 정상 데이터처럼 만들지는 않습니다.

SQL 정리는 데이터베이스에 연결하지 않습니다. 보기 좋게 정리됐더라도 실제 테이블·열이 존재하는지, 명령을 실행해도 안전한지는 확인한 것이 아닙니다. 업무용 연결 정보나 인증키는 예시로 공유하지 마세요.

#### 예제·선택 도움

같은 JSON의 축약/들여쓰기 예를 보여주고 문자열 안의 공백은 내용이라는 점을 설명한다. “문법 검사 통과=실행 안전” 배지는 만들지 않는다.

#### FAQ 추가·교체안


**SQL 문장이 잘 정리되면 실행해도 된다는 뜻인가요?**  
아닙니다. 이 도구는 글자 배치를 정리합니다. 실행 결과나 데이터 변경 위험은 실제 사용하는 데이터베이스 환경에서 별도로 검토해야 합니다.


**오류가 있는 JSON을 자동으로 고쳐 주나요?**  
데이터를 임의로 바꾸지 않고 오류를 안내합니다. 원본의 구조를 확인한 뒤 수정하고 다시 정리하세요.


**반영 전 확인:** 존재하는 JSON 자동복구 FAQ와 새 설명 중 중복은 합친다. SQL 실행 기능을 암시하지 않는다.

#### 게시용 추가 원고

##### 기간의 길이와 실제 일하는 날 수는 다릅니다

달력에서 두 날짜 사이의 일수와 주말·공휴일을 뺀 영업일 수를 구분해 확인하세요. 회사 창립기념일이나 부서 휴무처럼 회사만 쉬는 날은 별도 휴일로 추가해야 합니다.

연차 계산은 입력한 기준일과 산정 방식에 따른 참고 결과입니다. 발생한 연차와 이미 사용하고 남은 연차는 다르므로, 실제 잔여일수는 회사의 사용 내역과 함께 확인하세요. 새로 정해진 휴일이 반영됐는지도 계산 전에 확인하는 편이 좋습니다.

#### 예제·선택 도움

예시: 같은 날짜 범위를 두고 회사 휴무일 한 날을 추가했을 때 영업일 수가 어떻게 바뀌는지 보여준다. 실제 공휴일 날짜를 임의로 정해 사례에 쓰지 않는다.

#### FAQ 추가·교체안


**입사일 기준과 회계연도 기준 결과가 달라요.**  
연차를 묶어 계산하는 기준 기간이 다르기 때문입니다. 회사가 사용하는 기준을 먼저 확인하고, 발생·사용·정산 내역을 따로 살펴보세요.


**표시된 연차가 제가 남긴 연차인가요?**  
발생 구조를 계산한 참고값과 사용 후 잔여일수는 다릅니다. 실제 사용 내역과 회사 정산 기준을 함께 확인하세요.


**반영 전 확인:** 법령 수치·최신 휴일·정산 의무를 새로 단정하지 않는다. 기준 자료·적용 연도는 실제 로직과 공식 근거 확인 후 표시한다.


### 18. 글로벌 시차

경로: `/tools/timezone-calculator`

**보강 방향:** 현재 시각보다 회의 날짜·날짜 넘어감·추천 없음의 의미를 안내한다.

#### 게시용 추가 원고

##### 지금의 시차보다 회의가 열릴 날짜를 기준으로 확인하세요

해외 회의 시간을 정할 때는 도시뿐 아니라 날짜를 함께 선택하세요. 서머타임을 쓰는 지역은 시기에 따라 시차가 바뀔 수 있고, 한 지역의 저녁이 다른 지역에서는 다음 날 아침일 수 있습니다.

회의 후보가 나오면 각 도시의 현지 날짜와 시각을 함께 읽어 보세요. 추천 구간은 화면에 정해진 현지 업무시간을 비교한 결과이며, 해당 회사의 실제 근무표나 국가별 공휴일까지 확인한 것은 아닙니다.

#### 예제·선택 도움

예시 문장 형식: “서울: ○월 ○일 ○시 / 다른 도시: ○월 ○일 ○시”. 고정 시차 숫자 대신 실제 선택 결과가 들어가게 하며, 날짜가 다른 도시를 별도 표시한다.

#### FAQ 추가·교체안


**겹치는 시간이 안 나오면 오류인가요?**  
선택한 모든 도시에서 설정된 업무시간이 동시에 겹치지 않을 수 있습니다. 도시 수나 회의 날짜를 확인하고, 참여자와 가능한 시간을 별도로 협의하세요.


**공휴일에도 업무시간으로 추천되나요?**  
이 도구는 시차와 현지 업무시간을 비교하며 국가별 공휴일은 반영하지 않습니다. 회의를 확정하기 전에 각 지역의 휴무 여부를 확인하세요.


**반영 전 확인:** 현재 구현은 기본 현지09~18시·30분 간격·최대6도시. 사용자 조절 기능이 없는데 자유설정한다고 쓰지 않는다.


### 19. 급여 계산

경로: `/tools/payroll-calculator`

**보강 방향:** 기준일과 입력에 포함/제외할 항목을 결과 근처에서 설명한다.

#### 게시용 추가 원고

##### 통장에 들어오는 금액과 비교하기 전에 입력 기준부터 확인하세요

월 급여, 과세 대상 금액과 비과세 수당은 같은 값이 아닐 수 있습니다. 각 입력칸의 안내를 보고 해당하는 금액을 넣은 뒤, 결과의 보험료·세금 항목을 나눠 확인하세요.

이 결과는 입력 조건에 따른 간이 계산입니다. 회사의 신고 금액, 적용 기준, 실제 근태와 정산 방식 때문에 급여명세서와 다를 수 있습니다. 차이가 크다면 계산 결과 하나만 보기보다 입력 금액·부양가족·기준일과 명세서의 각 공제 항목을 함께 확인하세요.

#### 예제·선택 도움

결과 아래 “계산에 사용한 기준”에 실제 적용 연도/갱신일/입력 가정/제외 항목을 표시한다. 법령 수치와 세율은 원고에 하드코딩하지 않고 검증된 계산 데이터에서 가져온다.

#### FAQ 추가·교체안


**급여명세서와 조금 다르면 계산이 틀린 건가요?**  
먼저 입력한 급여의 기준과 실제 명세서의 과세·비과세·공제 항목이 같은지 확인하세요. 이 도구의 간이 계산으로 모든 회사의 신고·정산 차이를 반영할 수는 없습니다.


**결과를 회사의 최종 정산 근거로 써도 되나요?**  
사전 확인을 위한 참고값입니다. 실제 급여·퇴직 정산은 근무 기록과 적용 기준을 확인해 처리해야 합니다.


**반영 전 확인:** 법률·세율 검토를 수행하지 않은 상태에서 “최신 법정 금액” 보장 금지. 면책 문장만 늘리지 말고 실제 가정을 표시한다.


### 20. 개인정보 가리기

경로: `/tools/document-redactor`  
가이드 연결: `documentRedactor`  
우선순위: 높음

**보강 방향:** 이미 늘어난 중복 FAQ를 정리하고 공유 직전 검토 동작에 집중한다.

#### 게시용 추가 원고

##### 검정 표시를 넣은 뒤에도 마지막 확인은 필요합니다

이 도구는 개인정보를 자동으로 찾아 주지 않습니다. 같은 연락처나 이름이 다른 페이지·표·머리말에 반복되어 있는지 직접 확인하세요. 가린 표시가 없는 페이지가 안전하다고 판정된 것도 아닙니다.

결과를 만들면 PDF 전체 페이지가 이미지 기반으로 다시 저장됩니다. 검색·글자 선택·기존 서명·입력 양식·링크가 유지되지 않으므로 이 방식이 제출 목적에 맞는지 먼저 확인하세요. 공유할 때는 원본이 아니라 새 결과 파일을 고르고, 파일 이름에 민감한 정보가 남아 있지 않은지도 살펴보세요.

#### 예제·선택 도움

검토 예시: 한 페이지의 연락처만 가린 뒤 마지막 페이지의 서명란에도 같은 연락처가 남아 있는 합성 문서. “한 군데 가림=전체 자동 제거”가 아님을 보여준다.

#### FAQ 추가·교체안


**사진의 숨은 정보 제거와 무엇이 다른가요?**  
개인정보 가리기는 문서·이미지에 보이는 부분을 선택해 가립니다. 사진 메타데이터 제거는 파일 안에 저장된 촬영 위치·기기 같은 정보를 다룹니다. 목적에 맞는 도구를 고르세요.


**공유 전 무엇을 확인해야 하나요?**  
새 결과 파일인지, 모든 페이지를 확인했는지, 검정 표시의 가장자리에 글자가 남지 않았는지, 파일 이름에 개인정보가 없는지 확인하세요.


**반영 전 확인:** 원본이 “안전하게 보관된다”거나 취소하면 모든 데이터가 “즉시 폐기된다”는 일괄 보장 표현은 구체적인 수명 처리와 대조해 수정한다. 원본 미변경과 백업 보증은 다르다.


### 21. 사진 메타데이터 제거

경로: `/tools/image-privacy`  
가이드 연결: `imagePrivacy`  
우선순위: 중간

**보강 방향:** 숨은 촬영 정보와 사진에 보이는 정보의 구분, 원본/사본 전달 실수를 안내한다.

#### 게시용 추가 원고

##### 사진 속 모습과 파일에 담긴 촬영 정보는 따로 확인하세요

사진에 주소가 보이지 않아도 파일 안에 촬영 위치나 기기 정보가 들어 있을 수 있습니다. 이 도구는 JPG·PNG·WebP의 촬영 정보를 확인하고, 정보를 정리한 사본을 만듭니다. HEIC·HEIF는 현재 지원하지 않습니다.

사진에 직접 찍힌 얼굴·이름·주소는 이 작업으로 가려지지 않습니다. 그런 내용은 이미지 편집이나 개인정보 가리기로 처리하세요. 새 사진을 저장한 뒤에는 촬영 정보뿐 아니라 방향·색·화질도 확인하고, 공유할 때 원본과 사본을 혼동하지 마세요.

#### 예제·선택 도움

예시를 만들 때 실제 GPS 좌표·기기 소유자 이름을 쓰지 않는다. “보이는 정보/숨은 정보” 두 칸으로 구분해 도구 선택을 돕는다.

#### FAQ 추가·교체안


**제거 후 사진의 방향이나 용량이 달라질 수 있나요?**  
새 사본을 만드는 과정에서 표시 방향이나 파일 크기를 다시 확인해야 합니다. 저장한 사진을 열어 원하는 모습인지 확인하고 원본은 따로 보관하세요.


**촬영 정보가 없다고 나오면 사진에 개인정보가 없는 건가요?**  
그렇지 않습니다. 보이는 얼굴·주소·차량번호 등은 촬영 정보와 별개입니다. 사진 자체도 직접 확인하세요.


**반영 전 확인:** 실제 지원 파서·재인코딩 정책과 결과 보고를 확인. 모든 숨은 정보가 영구복구 불가하게 지워진다는 표현 금지.


### 22. 비밀번호 생성기

경로: `/tools/security-tools`  
가이드 연결: `security`  
우선순위: 중간

**보강 방향:** 이미 충분한 추정 점수 설명에 생성값 보관·입력 제한 확인 절차를 보완한다.

#### 게시용 추가 원고

##### 점수보다 실제 사용할 조건을 먼저 확인하세요

사용할 사이트가 허용하는 길이와 문자 종류를 확인한 뒤 비밀번호를 생성하세요. 생성된 값은 다른 곳에서 재사용 중인 비밀번호와 구분해 보관하고, 입력한 사이트에서 정상적으로 등록됐는지도 확인하세요.

강도 점수와 예상 해독 시간은 정해진 가정에 따른 비교값입니다. 계정이 유출됐는지, 로그인 시도가 제한되는지, 다른 보호 수단을 사용하는지까지 검사한 결과는 아닙니다. 실제 사용하는 비밀번호를 오류 제보나 예제에 적지 마세요.

#### 예제·선택 도움

실제 사용할 비밀번호를 예시 스크린샷에 게시하지 않는다. 길이/허용 문자 변경 전후의 UI만 합성 값으로 보여준다.

#### FAQ 추가·교체안


**점수가 높으면 유출 여부도 확인된 건가요?**  
아닙니다. 입력된 문자열의 패턴을 분석한 결과입니다. 유출된 계정이나 데이터베이스를 조회하는 기능이 아닙니다.


**페이지를 닫아도 만든 비밀번호를 다시 볼 수 있나요?**  
이 도구가 생성 이력을 보관하는 기능은 아닙니다. 사용하기로 한 값은 페이지를 닫기 전에 본인이 사용하는 안전한 보관 수단에 저장하세요.


**반영 전 확인:** “영구적으로 안 뚫림”, 예상 해독 시간을 실제 보호 기간으로 표시 금지. 클립보드 기록을 완전히 지웠다고 약속하지 않는다.


### 23. QR 생성·읽기

경로: `/tools/qr-studio`  
가이드 연결: `qr`  
우선순위: 높음

**보강 방향:** QR 개념보다 생성 후 디지털/인쇄 검증과 실제 목적지 확인을 추가한다.

#### 게시용 추가 원고

##### QR 이미지를 만든 뒤에는 사용할 크기로 읽어 보세요

QR에 넣을 링크나 문장을 입력하고 미리보기를 확인하세요. 링크에 오타가 있으면 QR이 정상적으로 만들어져도 잘못된 주소로 연결됩니다. 로고와 색을 바꾼 뒤에는 실제 사용할 크기와 배경에서 다시 읽어 보는 편이 좋습니다.

읽기 기능은 QR 안의 내용을 보여 주는 기능이지 연결된 사이트의 안전성을 판정하는 기능이 아닙니다. 링크를 열기 전에 주소와 목적지를 확인하세요. 인쇄할 QR은 종이에 출력한 샘플로도 확인해 주세요.

#### 예제·선택 도움

검토 순서: 입력 주소 철자 확인 → PNG 생성 → 휴대전화로 읽기 → 실제 인쇄 크기·배경에서 읽기. 현재 bulk의 자동 재해독 검증은 보존하되 모든 환경의 스캔 보증으로 확대하지 않는다.

#### FAQ 추가·교체안


**만든 뒤 QR 안의 주소를 바꿀 수 있나요?**  
생성된 이미지에는 만들 때의 내용이 들어갑니다. 내용이 달라지면 새 QR 이미지를 만들어 교체하세요. 연결된 서버의 리디렉션 관리 기능을 이 도구가 제공한다고 안내하지 않습니다.


**화면에서 읽히는데 인쇄물에서는 잘 안 읽혀요.**  
너무 작게 인쇄했는지, 여백·배경·로고가 코드와 겹치는지 확인하세요. 실제 인쇄할 크기로 샘플을 만들어 여러 번 읽어 보세요.


**반영 전 확인:** 임의 스캔 성공률·무조건 유효기간 없음·악성URL 차단 기능으로 홍보하지 않는다.


## 5. 실제 세부 경로별 고유 문구

다음은 기존 경로에 넣을 문구다. 별도 SEO 페이지를 새로 양산하라는 제안이 아니다. 기본 도구 본문을 통째로 복사하지 말고 이 작업에 필요한 설명·예시만 덧붙인다. `/ko`·`/en` 언어 접두사는 생략했다.


### PDF 합치기

경로: `/tools/pdf-editor/merge`

**제출 서류를 한 파일로 모으기**

신청서·증빙자료·안내문을 제출 순서대로 추가하세요. 파일 순서뿐 아니라 각 파일의 페이지 순서와 방향도 확인한 뒤 하나의 PDF로 저장합니다. 여러 문서가 합쳐지면 책갈피·입력 양식·링크 같은 고급 기능이 원본과 같지 않을 수 있으므로 결과를 다시 확인하세요.

편집 확인: 파일 순서와 페이지 순서의 차이, 결과 전체 페이지 수


### PDF 나누기

경로: `/tools/pdf-editor/split`

**연속된 쪽과 떨어진 쪽을 구분하기**

한 파일에서 2~4쪽만 필요하면 해당 범위를 선택하고, 1쪽과 5쪽처럼 떨어진 쪽은 필요한 페이지를 직접 선택하세요. 여러 범위를 만들 때는 범위별 결과 파일의 이름과 페이지 구성이 원하는 대로인지 확인하세요.

편집 확인: 현재 범위 입력 문법/체크 선택을 실제 UI와 맞춤


### PDF 페이지 삭제

경로: `/tools/pdf-editor/delete`

**삭제와 정보 가리기는 다릅니다**

불필요한 페이지를 문서에서 빼려면 페이지 삭제를 사용합니다. 한 페이지의 이름이나 연락처만 가리려는 경우에는 개인정보 가리기를 사용하세요. 삭제할 페이지를 확인하고 남은 페이지의 순서도 함께 점검하세요.

편집 확인: 페이지 삭제=일부 텍스트 삭제라는 오해 방지


### PDF 회전

경로: `/tools/pdf-editor/rotate`

**문서에 저장되는 방향을 확인하기**

가로로 스캔된 페이지를 골라 읽기 편한 방향으로 돌리세요. 일부 페이지만 방향이 다르면 그 페이지만 선택합니다. 저장한 PDF를 다시 열어 방향이 반영됐는지 확인하세요.

편집 확인: 화면 보기 회전과 결과 PDF 방향 구분


### 이미지→PDF

경로: `/tools/pdf-editor/image-to-pdf`

**영수증 사진을 한 문서로 정리하기**

사진을 읽을 순서대로 추가한 뒤 A4에 맞출지 원본 이미지 크기를 사용할지 고르세요. 세로·가로 사진이 섞였다면 방향과 여백을 확인하세요. 사진을 PDF로 묶는 것만으로 사진 속 글자가 검색 가능한 텍스트가 되지는 않습니다.

편집 확인: 사진 크기/종이 크기/순서/검색 가능 여부


### PDF→이미지

경로: `/tools/pdf-editor/pdf-to-image`

**페이지를 그림 파일로 쓰기**

문서의 페이지를 PNG나 JPG로 저장해 첨부하거나 이미지 편집에 사용할 때 쓰세요. 해상도를 높이면 작은 글자를 확인하기 쉬워질 수 있지만 원본에 없던 세부 내용이 복원되는 것은 아니며 결과 파일과 메모리 사용량도 늘어납니다. 필요한 페이지만 먼저 변환해 크기와 선명도를 확인하세요.

편집 확인: 본문/표/도장 누락 확인. ZIP 생성 성공=시각적 정확성 보증 아님


### PDF 문서 변환

경로: `/tools/pdf-editor/convert`

**목적에 맞는 결과 형식 선택**

문장 중심으로 다시 편집하려면 DOCX, 표를 손보려면 XLSX, 서식 없이 글자만 필요하면 TXT를 검토하세요. PDF의 문단과 셀은 좌표로 추정하므로 복잡한 표나 여러 단 문서는 원문과 다른 구조로 나올 수 있습니다. 날짜·금액·표의 행과 열은 원문과 대조하세요.

편집 확인: 형식 비교표 + 재검토해야 할 내용


### PDF OCR

경로: `/tools/pdf-editor/ocr`

**사진 속 글자를 검색 가능하게 만들기**

글자를 선택할 수 없는 스캔 문서에서 단어를 찾고 싶을 때 OCR을 사용하세요. 작업 후 흔한 본문 단어와 숫자 몇 개를 실제로 검색해 보세요. 흐리거나 기울어진 원본에서는 인식이 틀릴 수 있으므로 이름·날짜·금액을 자동 인식 결과만 믿고 옮기지 마세요.

편집 확인: 검색용 텍스트 추가와 원본 이미지 개선은 다름


### PDF 마무리

경로: `/tools/pdf-editor/finish`

**여러 표시를 함께 넣기 전에 미리보기 확인**

페이지 번호·머리글·워터마크·도장을 함께 적용할 수 있습니다. 각 표시의 위치가 겹치거나 본문을 덮지 않도록 먼저 한 페이지에서 확인하세요. 여러 파일을 처리할 때는 파일마다 페이지 크기와 방향이 다를 수 있습니다.

편집 확인: 조건별 파일·페이지 범위 확인


### 페이지 번호

**표지와 본문의 번호를 나누어 생각하기**

편집 확인: 물리 페이지와 표시 번호의 차이


### 머리글·바닥글

### 홈

경로: `/{ko,en}/`

**이럴 때 Worklazy Tools를 사용하세요**

매달 모이는 엑셀 자료를 합치거나, 제출할 PDF에서 필요한 페이지만 남기거나, 여러 번 수정한 문서의 차이를 확인할 때 사용할 수 있습니다. 반복되는 파일 작업을 하나씩 처리할 수 있도록 문서·표·이미지·텍스트 도구를 모았습니다.

무엇을 골라야 할지 모르겠다면 결과를 먼저 생각해 보세요. “한 파일로 모으기”는 병합, “달라진 내용 찾기”는 비교, “같은 양식으로 여러 문서 만들기”는 워드 일괄 생성이 맞습니다. 작업 뒤에는 결과 파일을 확인하고 중요한 원본은 따로 보관하세요.

반영 위치·주의: 11개 도구 카드 아래에 실제 작업 흐름 3개: 월별 취합 / 수정본 검토 / 공유 전 가리기. hero 위에 긴 글을 올리지 않는다.


### 전체 도구

경로: `/tools`

**어떤 도구가 필요한지 헷갈리나요?**

이름이 비슷해도 결과는 다릅니다. 병합은 여러 자료를 모으고, 비교는 두 자료의 차이를 찾으며, 정리는 불필요한 공백·중복·행과 열을 다듬습니다.

문서나 사진에 보이는 이름·연락처를 가리려면 개인정보 가리기를, 사진 파일 안의 촬영 위치·기기 정보를 정리하려면 사진 메타데이터 제거를 사용하세요. 이미지로 저장하기와 이미지 속 글자를 읽는 OCR도 서로 다른 작업입니다.

반영 위치·주의: 각 카테고리 설명 한 문장+도구 선택 비교표. 검색 결과가 없을 때는 검색어·다른 도구 안내만 짧게; 빈 결과 화면의 광고 적합성은 별도 판단.


### 서비스 소개

경로: `/about`

**작은 반복 작업을 쉽게 끝내도록**

Worklazy Tools는 파일을 합치고, 내용을 비교하고, 공유할 자료를 정리하는 반복 작업을 브라우저에서 처리하도록 만든 도구 모음입니다. 간단한 작업을 위해 여러 프로그램을 오가야 하는 번거로움을 줄이는 데 초점을 맞췄습니다.

전문 편집 프로그램의 모든 기능을 대신하지는 않습니다. 각 도구에서 지원하는 파일과 보존 범위를 안내하고, 결과를 직접 확인할 수 있도록 제공합니다. HWP·오피스 같은 편집기는 공개된 편집 구성요소를 활용하며, 사용한 구성요소와 고지는 라이선스 페이지에서 확인할 수 있습니다.

반영 위치·주의: 실제 운영 주체 표기·지원 채널·검증된 업데이트 내역은 사실 확인 후 추가. 거짓 사용자 수/속도/전문가 검수/최초·유일 표현 금지.

## 7. 문구와 함께 만들면 가치가 커지는 예제

아래는 새로 제작할 자료 제안이다. 현재 다운로드 링크가 있다는 뜻이 아니다. 실제 엔진으로 결과를 만든 뒤 검증된 파일만 제공한다.

| 예제 묶음 | 입력 | 확인할 결과 |
|---|---|---|
| 월별 엑셀 취합 | 같은 열의 작은 합성 XLSX 2개 | 시트별/세로/가로 결과 차이 |
| 목록 비교 | 순서와 수량만 다른 상품코드 목록 | 일치/변경/중복의 의미 |
| 워드 일괄 생성 | 단순 DOCX와 가상 인물CSV | 값 연결·샘플·파일명·개별DOCX |
| PDF 페이지 정리 | 큰 페이지 번호와 도형을 넣은 합성PDF | 순서·범위·삭제·회전 |
| 스캔/OCR 확인 | 권리 문제가 없는 합성 스캔형 페이지 | 이미지변환과 글자검색의 차이 |
| 텍스트 정리 | 줄바꿈 문장과 한 줄 한 항목 목록 | 적합한 작업 선택 |
| QR 라벨 | 가짜 상품명과 테스트용 문자열 | 행별PNG·보고서·라벨 배치 |

실제 사용자의 계약서·급여자료·개인정보·비밀번호·문서 스크린샷은 예제로 쓰지 않는다. 성공 사례·시간 절약률·오류율·성능 수치는 직접 측정하고 조건을 기록한 것만 게시한다.

## 8. 반영 순서와 완료 기준

**1단계 — 사실과 동작의 모순 수정:** 문서 비교 제목, 오피스 자산 용량·시작/종료 설명, About 저장·테마 설명, 중복 FAQ를 먼저 정리한다.

**2단계 — 설명 부족이 큰 도구:** PDF 비교, 워드 일괄 생성, 오피스 편집기, PDF 이미지/OCR와 문서 변환의 차이, 엑셀 결과 검토를 우선 보강한다.

**3단계 — 도구별 예제:** 각 도구에 최소한 하나의 실제 질문에 답하는 선택 기준 또는 입력→출력 예제를 배치한다. 개수를 채우기 위한 형식적 조건이 아니라 편집 체크다.

**4단계 — 노출 연결:** guides의 블록·FAQ·경로별 ID와 실제 UI·정적 HTML을 함께 검증한다. JSON-LD만 추가하거나 화면에서 사라지는 숨은 SEO 원고를 만들지 않는다. 화면과 크롤러에 다른 내용을 제공하지 않는다.

**5단계 — 사용자·정책 확인:** 선택/저장 버튼을 가리는 장문·광고가 없는지, 동적 오류 화면에 광고가 남는지, 보호된 편집 화면의 기존 정책이 유지되는지 확인한다.

완료 확인 질문:
- 사용자가 무엇을 준비하고 어떤 선택을 해야 하는지 알 수 있는가?
- 결과 파일의 형식·달라지는 점·직접 확인할 부분이 분명한가?
- 다른 도구의 글을 제목만 바꾸어 반복한 내용은 아닌가?
- 실제 기능·지원 범위·최신 UI와 문구가 일치하는가?
- guide의 모든 새 항목이 올바른 경로·언어의 화면과 정적 본문에 보이는가?
- 영어 원고에도 같은 의미가 반영됐는가? 미지원 언어 경로를 억지로 만들지는 않았는가?
- 사실을 확인하지 않은 보안·속도·호환성·승인 보장이 없는가?

## 9. 근거와 검토 범위

### 저장소 확인 위치

기준 커밋 아래 파일을 중심으로 목록·경로·문구·연결을 확인했다.

이 문서는 모든 도구의 처리 엔진을 새로 테스트한 결과가 아니다. 지원 범위는 코드와 안내의 선언을 토대로 작성했으며, 구체적인 결과 예제는 반영 전에 실제 기능으로 확인해야 한다.

- 동의어, 다른 세부 작업, 문제 해결형 질문을 구분한다.
- 같은 의도·언어의 주 담당 URL을 정하되 하나의 URL은 여러 관련 작업을 설명할 수 있다.
- 메뉴명과 검색 제목을 동일하게 만들 필요는 없다. 검색 제목은 자연스럽게, 메뉴는 짧게 유지한다.
- 후보 목록을 meta keywords·숨김 본문·키워드 나열 문단으로 출력하지 않는다.
- 공백 유무·동의어·도시·확장자 조합만 바꾼 복제 페이지를 만들지 않는다.
- 검색어 미지원 의도는 SEO 목표에서 제외한다. 이는 검색 차단이나 광고의 제외 키워드 설정이 아니다.
- 검색 유입용 제목은 실제 도구·본문·초기 HTML·canonical·내부 링크와 일치시킨다.
- 월간 검색수와 자기 사이트 노출수는 다른 지표다. 알 수 없는 값은 0이 아니라 null로 둔다.
- 도구 성과 분석을 확장하면 동의·개인정보처리방침과 함께 검토하고 파일명·내용·입력값은 수집하지 않는다.

## 2. 현재 main에서 우선 확인할 두 가지

최신 커밋은 엑셀 병합에 “엑셀 시트 합치기”, “엑셀 자료 합치기” 표현을 반영했습니다. 다만 “부서별 엑셀 자료 합치기로 취합할 때”처럼 검색어를 그대로 끼워 넣어 어색해진 문장은 “부서별 엑셀 자료를 하나로 합칠 때”처럼 자연스럽게 고치는 편이 낫습니다.

`canonicalSeoPath()`는 PDF 페이지 번호·머리글/바닥글·워터마크·도장 경로를 `/tools/pdf-editor/finish`에 통합합니다. 독립 검색 유입 페이지로 운영할지, 편의용 프리셋으로 유지할지 먼저 결정해야 합니다. canonical은 검색엔진에 보내는 신호이며 결과를 강제하지 않습니다.

이전 분석에서 확인한 정적 페이지 생성 경로는 제목·설명·기능 목록·선택된 FAQ를 사용합니다. 새 본문을 작성할 때는 런타임 가이드와 초기 HTML이 동일한 내용 소스를 사용하도록 확인해야 합니다.

- title: 엑셀 파일 합치기·시트 병합 | Worklazy Tools

## 7. 검색 실적 검증

실제 검색량은 네이버 키워드 도구와 Google Keyword Planner 등의 원자료로 별도 검증합니다. Google Search Console에서는 자신의 사이트가 어떤 검색어·페이지에 노출되고 클릭됐는지를 확인합니다. 미노출 검색어의 시장 전체 수요를 GSC로 계산할 수는 없습니다.

변경 전 최근 28일을 기준으로 보관하고, 같은 국가·기기·브랜드 구분으로 비교합니다. 표본이 적으면 90일도 함께 봅니다. 먼저 기술적 색인 상태를 확인하고, 그 뒤 의도·본문·제목·내부 링크를 순서대로 검토합니다. 이 기간은 운영 제안이지 검색엔진의 의무 대기 기간이 아닙니다.

추가 분석 이벤트가 필요하면 동의와 개인정보처리방침부터 함께 검토합니다. 파일명, 문서 내용, 비밀번호, 급여, QR의 원문 값을 분석 이벤트로 보내지 않습니다.

## 9. 코드 반영 순서

1. 이 맵에서 각 의도와 담당 URL을 확정합니다. 대표·동의어·세부 작업·질문을 섞지 않습니다.
2. PDF finish와 세부 네 경로의 대표 URL 정책을 결정합니다.
3. 기존 경로를 유지하며 title·description·H1·본문 예시를 함께 수정합니다. 모든 동의어를 문장에 그대로 넣지 않습니다.
4. 초기 HTML과 React 화면의 본문·FAQ·제목·canonical·언어별 링크를 확인합니다. JSON-LD에만 내용을 넣지 않습니다.
5. sitemap에는 정한 대표 정책과 일치하는 URL을 반영하고, 직접 들어갈 수 있는 내부 링크를 유지합니다.
6. 배포 전후의 실적을 보관하고 실제 조회 검색어로 우선순위를 갱신합니다.
